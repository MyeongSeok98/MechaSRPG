# 무기 탄약과 재장전

## 설정
Project에서 WeaponData 에셋을 선택한다. 기존 **공격 AP 비용**이 발사 비용이다. 원거리 무기에 다음 필드가 추가됐다.

| Inspector 항목 | 의미 | 새 필드 기본값 |
|---|---|---|
| 장탄 수 (발/탄창·팩) | 한 번 장전한 상태에서 발사 가능한 횟수 | 6 |
| 권장 예비 개수 (기체별 설정의 기본값) | UnitWeaponLoadout의 예비 개수가 -1일 때 사용하는 권장값 | 2 |
| 빈 무기 본체 중량 (t) | 탄약을 제외한 무기 무게 | 기존 중량 값 유지 |
| 만탄 탄창·팩 1개 중량 (t) | 장전/예비에 공통으로 사용하는 만탄 탄창·에너지 팩 하나의 무게 | 0 |
| 재장전 AP 비용 | 선택한 무기를 재장전하는 데 드는 AP | 3 |

모두 무기별 값이다. 예를 들어 빔 라이플을 장탄6/재장전3, 실탄 라이플을 장탄12/재장전2로 직접 설정할 수 있다. 분류를 바꿨다고 기존 설정값을 자동 덮어쓰지 않는다. 기존 무기 에셋의 발사 AP·피해·사거리 등은 변경하지 않았다. 기존 에셋에 새 값이 저장되어 있지 않으면 위 기본값을 사용한다.

빔은 에너지 팩, 실탄과 폭발물은 탄창으로 표시한다. 근접은 탄약을 사용하지 않는다. 한 번 사격할 때1발이며 연사/발사체별 소모는 별도 기능이다.

기체의 **UnitWeaponLoadout → 왼손/오른손 → 예비 탄창·팩 개수**에서 실제 출격 예비 개수를 설정한다. `0`은 예비 없음, `3`은 예비 3개다. `-1`은 무기 데이터의 권장값을 사용하며 전투 시작 때 그 기체에 확정한다. 같은 무기를 공유해도 기체별·손별 개수를 다르게 설정할 수 있다. 전투 중 이 설정은 변경할 수 없다.

## 중량 계산 (B 방식)

```text
손 무기 = 빈 무기 본체 + (장전 1개 + 선택한 예비 개수) × 만탄 탄창·팩 1개 중량
백팩 = 백팩 자체 + 포함 무기 본체 + 장전 탄창·팩 1개 (예비 0)
총 장착 중량 = 왼손 + 오른손 + 백팩
```

예: 빈 라이플 2톤, 탄창 0.5톤, 예비 2개면 `2 + (1 + 2) × 0.5 = 3.5톤`이다. 예비를 0개로 줄이면 2.5톤이다. 양손 무기는 한쪽 슬롯에만 지정하여 한 번 계산한다. 근접 무기는 탄약 무게를 계산하지 않는다. 기체 자체 중량은 장착 중량에 포함하지 않는다.

기체의 장착 중량 한도가 양수이면 탄약까지 합산해 초과 장착·출격을 차단한다. 한도 0은 제한 미설정이다. 기존 초과 구성은 예비 개수를 단계적으로 줄여 복구할 수 있다. 무기와 예비 개수는 Inspector에서 함께 변경할 수 있으며 한 기체라도 한도를 초과하면 다중 편집 전체를 거부한다.

코드에서는 전투 시작 전에 `TryConfigure(left, leftGrip, right, rightGrip, leftSpareMagazines, rightSpareMagazines)`로 무기와 예비 개수를 한 번에 지정한다. 이미 선택한 무기의 예비 개수만 변경할 때는 `TryConfigureSpareMagazines(leftCount, rightCount)`를 사용한다. 두 API 모두 중량 한도를 검사한다. 기존 4인자 `TryConfigure`는 기존 무기의 개수를 보존하고 새 무기는 권장 개수로 설정한다.

이는 **출격 구성 중량**이다. 전투 중 사격·재장전으로 잔탄이나 예비가 줄어도 이 중량을 낮추지 않는다. 기존 무기 에셋은 수정하지 않았으며 새 탄창 중량의 기본값은 0이다. 실제 밸런싱 시 본체와 탄창 중량을 각각 입력한다.

## 플레이 흐름
- 일반 사격·경계사격 모두 명중/빗나감과 관계없이 실제 발사 시1발 소모한다. 조준/범위 확인/Skip/실패한 공격은 소모하지 않는다.
- 유닛 선택 → **Reload** → 옆 메뉴에서 장착 무기를 선택한다. 양손 무기는 한 번만 표시된다.
- 남은 탄약을 버리고 예비1개로 만탄을 장전한다. 탄창이 이미 가득 찼거나 예비/AP가 없으면 재장전할 수 없다. 빈 탄창은 발사·경계 진입이 불가능하다.
- 자기 턴에 정상 행동할 수 있을 때만 재장전한다. 이동/도착 방향 선택/경계/반응 사격 결정 중 또는 Critical/파괴/탈출 상태에서는 할 수 없다. ESC는 기존처럼 기체 선택을 취소하며 자원은 소모하지 않는다.
- 경계사격은 진입AP2 외에 발사AP를 추가로 쓰지 않지만 매번 탄약1발을 쓴다. 마지막 발을 쏜 뒤 경계가 종료된다. 경계 중 자동 재장전은 없다.
- 적은 즉시 가능한 공격을 우선한다. 탐지한 적이 있고 즉시 공격하지 못하면 빈 원거리 무기를 재장전하고 남은 AP로 판단한다. 적을 탐지하지 못한 경우 기존 대기를 유지한다.

## 데이터와 상태
WeaponData는 무기·탄창 사양과 권장 예비 개수를 저장한다. UnitWeaponLoadout은 기체별 출격 예비 개수와 장착 중량을 관리한다. UnitWeaponAmmo가 장착 설정에서 시작 개수를 받아 각 기체·각 장착 무기의 현재 탄약을 관리한다. 같은 정의를 두 기체 또는 두 손이 공유해도 잔탄/예비는 독립이다. 무기가 손을 옮기거나 파지만 바뀌면 기존 잔탄과 예비를 유지한다. 턴/AP 초기화나 같은 BattleUnit 재초기화로 탄약이 차오르지 않는다.

탄약 설정은 장착 상태를 처음 만들 때 복사한다. 장착한 무기 정의의 종류/탄약 설정을 편집하며 시험할 때는 전투를 다시 시작한다. 전투 중 인벤토리 교체/탄창 회수/기지 보급/소지 재고 제한은 아직 구현하지 않았다.

- Unit/UnitWeaponLoadout.cs: 기체별 출격 예비 개수·탄약 포함 중량·한도 검증.
- Unit/UnitWeaponAmmo.cs: 잔탄/예비·손 이동 보존.
- Combat/CombatSystem.cs: 사격 자원 소모·재장전 권한/AP.
- AI/EnemyAIController.cs: 적의 빈 탄창 재장전.

- Presentation/BodyTargetUI.cs, BattleDebugUI.cs: 탄약 표시.

경로는 Assets/_Game/Scripts 기준이다. 사용자 씬·모델·카메라·이동 속도·장갑·무기 수치는 보존했다.
