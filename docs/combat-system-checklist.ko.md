# MechaXCOM 전투 시스템 개발 체크리스트

기준일: 2026-11-09

현재 상태: 이동·공격·부위 손상·탄약·엄폐·시야·경계를 조합해 전투를 진행할 수 있는 프로토타입.

체크된 항목은 구현된 기능이고, 체크되지 않은 항목은 아직 구현하지 않은 기능이다. 아래 미구현 항목은 개발 후보 목록이며, 모두 구현하기로 확정한 범위는 아니다. 세부 규칙과 수치는 각 기능 작업 전에 결정한다.

## 권장 진행 순서

1. 임무 목표와 소대 철수
2. 전투 UI의 Unity 적용
3. 엄폐를 고려한 AI와 전장 요소 확장

## 1. 기체별 이동 효율

현재: MechaData의 AP당 이동거리를 실제 비용에 적용한다. 자기 턴 동안 이동 비용을 누적하고, 먼저 지불한 이동 여유는 이동·공격·이동을 나눠도 유지한다. 다리 하나 파괴 시 다음 칸부터 효율 절반, 둘 다 파괴 시 이동 불가다. 최종 효율 함수를 두어 미래 부품 보정을 연결할 수 있다.

- [x] MechaData의 AP당 이동거리를 실제 이동 비용에 적용
- [x] 이동 가능 범위·경로·예상 AP가 같은 이동 비용 규칙을 사용하도록 연결
- [x] 다리 파괴에 따른 이동 제한과 기체별 이동 효율을 함께 검증

## 2. 기체별 탐지 성능

현재: MechaData의 기본 탐지 거리를 전투 시작 시 UnitVision에 적용한다. 기본10칸이며0도 허용한다. MechaData가 없는 유닛은 기존 UnitVision 설정을 유지한다. 추가부품 보너스와 머리 손상에 따른 탐지 감소는 아직 구현하지 않았다.

- [x] 기체 데이터에 탐지 거리 정의
- [x] 전투 시작 시 기체의 탐지 거리를 UnitVision에 적용
- [x] 기체별 탐지 차이가 적 발견과 전장의 안개에 반영되는지 검증

## 3. 임무 규칙

현재: MissionController가 공통 아군 전멸 실패와 임무별 성공·실패 요청을 처리하고 TurnManager가 전투를 중단한다. 기존 씬은 적 전멸 자동 성공을 유지한다. MissionData와 씬 EnemyUnitGroup/MissionTarget을 연결한 섬멸·특정 메카/시설 파괴 목표 및 실행 상태·진행도 표시를 구현했다. 호위·복합 목표와 별도 결과 화면은 아직 없다.

- [x] 임무 결과·실패 이유·완료 이벤트와 공통 아군 전멸 실패, TurnManager 종료 요청 연결

- [x] MissionData와 전투별 목표 실행 상태 분리 — 지정 적 집단 섬멸 구현
- [x] 특정 목표 파괴 — 통신소 단일 HP·폭발 공격·적 생존 중 성공·2대2 테스트 씬
- [ ] 거점 점령 목표
- [ ] 호위 또는 특정 대상 보호 목표
- [ ] 지정 턴까지 생존하거나 턴 제한 안에 완료하는 목표
- [ ] 지정 지점 도달·탈출 목표
- [ ] 임무 목표 진행 상황과 종료 이유 표시

각 목표 유형은 후보이며 첫 임무에 전부 넣을 필요는 없다.

## 4. 소대 철수

현재: 개별 파일럿의 긴급탈출은 가능하다. 소대 전체의 임무 철수는 없다.

- [ ] 소대 철수 조건과 확정 흐름 구현
- [ ] 철수 시 임무 결과 및 생환 기체·파일럿 기록
- [ ] 승리·실패·철수 결과 구분

## 5. 파일럿 생존 결과

현재: 기체 파괴와 파일럿 사망은 연결되어 있지 않다. 긴급탈출 후 임무 결과 처리도 없다.

- [ ] 기체 파괴·탈출 상황에 따른 파일럿 결과 판정
- [ ] 생존·부상·실종·포로·사망 결과 정의 및 처리
- [ ] 전투 결과를 전투 이후 파일럿 상태에 전달

## 6. 공격 방식 확장

현재: 직사 폭발물은 한 기체의 직격/추가 부위 피해를 설정한다. 곡사는 좌표 중심 마름모 범위의 아군·자신·미탐지 적도 피격하고 기체별 부위 수와 부위당 피해를 추첨한다. 무기별 반경·최소/최대 부위 수를 설정하며 건물은 폭발을 차단한다. 미탐지 정보는 미리보기·결과에 노출하지 않는다.

- [x] 직사 폭발무기의 무작위 추가 부위 피해와 최종 상태 일괄 판정

- [x] 폭발 범위와 범위 내 대상 피해 처리
- [x] 맵 좌표 지정 공격
- [ ] 근접 교전 상태와 행동 제한
- [ ] 근접 교전 이탈 규칙

직사·곡사·범위 공격과 근접 이탈의 구체적인 규칙은 별도 설계가 필요하다.

## 7. 전장 요소

현재: 엄폐·장애물·이동 불가 지형과 엄폐물 HP·폭발 파괴를 지원한다. 지형별 이동 비용은 없다. 독립 배치한 엄폐물에는 CoverDurability를 추가해야 한다.

- [x] 엄폐물 내구도와 파괴 처리 — 프리팹별 최대 HP, 직사 선택/곡사 범위 폭발 피해
- [x] 엄폐물 파괴 후 엄폐 판정 갱신 — 충돌·이동·사선·시야·범위 표시 갱신, 겹친 다른 장애물 유지
- [ ] 도로·진흙 등 지형별 이동 비용
- [ ] 지형 비용을 반영한 경로 탐색과 이동 범위 표시
- [ ] 부스트 행동과 자원·사용 조건

## 8. 적 AI 확장

현재: 기본적인 탐지·사거리 접근·공격·재장전·대기를 지원한다. 아래 전술 판단은 구현하지 않았다.

- [ ] 엄폐를 고려한 위치 선택
- [ ] 우회·측면 접근
- [ ] 후퇴 및 생존을 위한 판단
- [ ] 여러 적 기체의 집중 공격 판단
- [ ] 적 AI의 경계 선택

## 9. 장비 운용 확장

현재: 손 무기와 백팩의 중량 제한이 적용된다. 장전·예비 탄약 무게를 합산하며 예비 개수는 기체별로 선택한다. 전투 중 수동 장비 전환은 없다.

- [x] 예비 탄창·에너지 팩의 중량 데이터와 총 장착 중량 반영
- [ ] 전투 중 수동 무기 교체
- [ ] 한손·양손 겸용 무기의 수동 파지 전환

팔 파괴 시 겸용 무기를 양손에서 한손으로 바꾸는 자동 처리는 이미 구현되어 있다.

## 10. 방향별 부위 명중률 보정

현재: 이동 중 기체 회전과 이동 후 최종 방향 선택은 구현되어 있다. 방향에 따른 부위 명중률 보정은 없다.

- [ ] 공격 방향과 대상 기체 방향으로 부위 노출 방향 판정
- [ ] 방향별 부위 명중률 배율 적용
- [ ] 조준 미리보기와 실제 공격에 같은 방향 보정 적용

이 보정은 이전에 구현을 보류한 기능이다. 재개 여부와 수치는 별도로 결정한다.

## 11. 파일럿 패시브

현재: 패시브 인터페이스·상황 정보·효과 평가 구조는 준비되어 있지만 실제 전투 효과는 연결되지 않았다.

- [ ] 파일럿에 패시브를 지정하는 데이터 연결
- [ ] 패시브의 AP·명중률·피해 보정을 공통 전투 계산에 적용
- [ ] 미리보기와 실제 소모·판정에 동일 효과 반영
- [ ] 효과 중첩과 최솟값·최댓값 규칙 검증

## 12. 전투 UI와 외형 연결

현재: Unity의 기본 행동·조준 UI는 있다. 새 HTML HUD는 독립된 시연이며 Unity에 연결하지 않았다.

- [ ] 새 HUD의 Unity 레이아웃 구현
- [ ] 선택 기체·파일럿·AP·부위 HP·무장·잔탄을 실제 상태에 연결
- [ ] 조준 패널의 명중률·피해·소모 자원과 사격 확정 연결
- [ ] 행동 불가·탄약 부족·사거리 밖·중량 초과 등의 사유 표시 정리
- [ ] 무기 데이터와 장착 무기 외형의 자동 동기화
- [ ] 백팩 모델 자동 장착과 장착점 연결

## 현재 보류하거나 이번 목록에서 제외한 기능

- 방패: 사용자 결정으로 보류
- 중량에 따른 이동력 감소: 현재 적용하지 않음. 중량 초과 장착·출격 차단만 구현
- 기체 전체 Heat 시스템: 현재 게임 방향의 핵심 시스템으로 사용하지 않음
