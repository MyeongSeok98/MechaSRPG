# 부위 HP, 전투불능과 긴급탈출 설계

## 목적과 범위

기존 전체 HP를 제거하고, 조준한 부위의 HP와 기체 상태로 피해 및 전투 지속 여부를 판단한다.
플레이어는 ACTIVE 상태에서 싸우거나 탈출할 수 있으며, CRITICAL 상태에서는 AP를 써서 파일럿을 탈출시키는 판단을 한다.
원거리 부위 조준 UI, 근접 공격, 진영별 턴, 적 AI와 기존 샘플 씬에 연결한다.

이번 범위에는 파일럿 탈출 여부만 포함한다. 파일럿 능력치·부상·영구 사망·자동 탈출 확률·임무 후 회수·수리·세이브는 만들지 않는다.
부스트는 현재 구현되어 있지 않으므로 새 부스트 시스템을 추가하지 않는다. CRITICAL은 일반 전투 행동을 허용하지 않는 상태로 정의한다.
주요 부위 0~2개 파괴 시에는 개별 능력 저하를 추가하지 않고 현재 전투 성능을 유지한다.

## 승인된 초기 수치

| 부위 | 최대 HP | 원거리 조준 패널티 |
|---|---:|---:|
| Body / Torso | 20 | 0%p |
| Cockpit | 6 | 45%p |
| Head | 6 | 15%p |
| LeftArm / RightArm | 각각 8 | 각각 10%p |
| LeftLeg / RightLeg | 각각 10 | 각각 10%p |

Body와 조준 UI의 Torso는 같은 부위다. 별도 전체 HP 또는 부위 HP 합계 체력은 존재하지 않는다.
Whole은 부위가 아니라 기본 조준 모드이며 피해를 Body에 적용한다.
근접 공격은 Body만 공격한다. 피해 8, 기본 명중률 95%, AP 3, 사거리 2, 엄폐 무시와 기존 기동 회피 적용을 유지한다.
원거리는 현재 피해 5, 기본 명중률 80%, AP 3, 사거리 7을 유지하며 조준한 부위에만 피해를 적용한다.
엄폐·기동 회피를 계산한 원거리 확률에서 부위 패널티를 차감하고 최소 0%로 제한한다.
따라서 평지의 기본 콕피트 명중률은 35%, Full Cover에서는 5%다. 피해 5 두 번 명중하면 콕피트가 파괴된다.

## 부위 피해

- 피해는 지정된 부위에만 적용하고 HP는 0 이하로 내려가지 않는다. 초과 피해는 다른 부위로 넘기지 않는다.
- 주요 부위는 Head, LeftArm, RightArm, LeftLeg, RightLeg의 서로 다른 5개다.
- Body와 Cockpit은 주요 부위 파괴 개수에 포함하지 않는다.
- 주요 부위 HP가 처음 0이 되었을 때 파괴 개수를 증가시킨다. 같은 부위를 재공격해도 개수는 증가하지 않는다.
- 이미 파괴된 부위를 조준할 수 있지만 추가 부위 피해는 0이다. CRITICAL 기체가 명중당한 경우에는 아래 재판정 규칙을 적용한다.
- 빗나간 공격은 부위 HP, 상태, 파괴 판정 난수를 변경하지 않는다. 공격 AP는 기존처럼 소비한다.

## 상태 전환과 판정 순서

기체 상태는 ACTIVE, CRITICAL, DESTROYED, EJECTED로 관리한다.
EJECTED는 파일럿이 탈출해 현재 전투에서 사용 불가능한 기체이며 DESTROYED와 구분한다.

1. Body 또는 Cockpit이 0이면 즉시 DESTROYED. 다른 확률 판정은 하지 않는다.
2. 주요 부위 파괴 개수가 4개 이상이면 즉시 DESTROYED. 다른 확률 판정은 하지 않는다.
3. ACTIVE에서 세 번째 주요 부위가 파괴되면 CRITICAL에 진입하고 완전파괴 여부를 한 번 판정한다.
4. 이미 CRITICAL인 기체에 공격이 명중하면 완전파괴 여부를 한 번 다시 판정한다. 실제 부위 피해가 0이어도 명중이면 재판정한다.
5. 위 치명 조건이 없는 ACTIVE 기체는 그대로 ACTIVE다.

완전파괴 확률은 초기 25%이며 Inspector에서 조절한다.
0~99 정수 난수 중 0~24면 DESTROYED, 25~99면 CRITICAL을 유지한다.
한 번의 명중에서 CRITICAL 진입 판정과 추가 명중 판정을 중복 실행하지 않는다.
이미 DESTROYED 또는 EJECTED이면 공격 대상과 상태 변경 대상에서 제외한다.
명중 난수와 완전파괴 난수는 별도로 관리하고 테스트에서 경계값을 결정적으로 주입한다.
DESTROYED가 파일럿 사망을 의미하지는 않는다. 자동 사망 또는 자동 탈출을 이번에 추정하지 않는다.

## 행동과 긴급탈출

| 상태 | 선택·상태 확인 | 이동·공격 | 긴급탈출 | 공격 대상 |
|---|---|---|---|---|
| ACTIVE | 가능 | 자기 진영 턴에 가능 | 자기 진영 턴에 가능 | 가능 |
| CRITICAL | 가능 | 불가능 | 자기 진영 턴에 가능 | 가능 |
| DESTROYED | 전투 선택 제외 | 불가능 | 불가능 | 불가능 |
| EJECTED | 전투 선택 제외 | 불가능 | 불가능 | 불가능 |

- 긴급탈출은 AP 1을 소비하며 파일럿 탈출 상태와 EJECTED 전환을 한 번만 기록한다.
- AP 0이면 버튼을 비활성화한다. 해당 진영의 다음 턴 시작에 ACTIVE와 CRITICAL 기체의 AP를 기존 최대값으로 회복한다.
- 다른 진영 턴, 이동 중, 전투 종료 후에는 탈출할 수 없다.
- CRITICAL에 진입하거나 DESTROYED/EJECTED가 되면 진행 중인 이동을 중단한다. 이동 속도 값은 변경하지 않는다.
- 탈출 후 현재 전투에서 재탑승하거나 기체를 다시 활성화하는 기능은 없다.
- 이번 적 AI에는 자동 긴급탈출 전략을 추가하지 않는다. CRITICAL 적은 행동을 건너뛴다.

## 점유, 턴과 승패

CRITICAL은 공격 대상으로 남아야 하므로 모델·Collider와 그리드 점유를 유지한다.
DESTROYED와 EJECTED는 그리드 점유를 해제하고 모델·Collider를 비활성화해 전투에서 제외한다.
GameObject를 즉시 Destroy하지 않고 전투 종료까지 상태와 탈출 정보를 보존한다. 새 잔해나 지형 장애물은 만들지 않는다.

자동 승패는 ACTIVE 또는 CRITICAL 기체가 남아 있는지를 기준으로 한다.
CRITICAL만 남았다는 이유로 전투를 끝내면 추가 공격과 마지막 아군의 긴급탈출이 차단되므로 즉시 종료하지 않는다.
한 진영의 모든 기체가 DESTROYED/EJECTED로 전투에서 이탈하면 기존 승리·패배 판정을 확정한다.
양쪽에 CRITICAL만 남아도 플레이어는 턴 종료로 AP를 회복하고 탈출할 수 있다. 적 CRITICAL은 계속 행동을 건너뛴다.
이 연결 규칙은 설계 검토 후 구현계획 작성 요청과 함께 승인된 범위로 사용한다.

## 책임과 기존 자산 연결

- UnitHealth: 기존 단일 HP 구현을 부위별 최대/현재 HP, 기체 상태, 파괴 개수, 피해 결과, 상태 변경 이벤트로 교체한다.
  클래스와 Script GUID는 유지해 기존 씬·프리팹 참조를 보존한다. 기존 maxHealth 직렬화 값은 Body 최대 HP로 이전하며 전체 HP 필드는 제거한다.
- BattleUnit: 전투 행동 가능, 공격 대상 가능, 선택 가능, 탈출 가능을 구분하고 상태 변경 시 이동·점유·표현을 처리한다.
- CombatSystem: 근접/기본 조준을 Body에 연결하고 원거리 부위 피해와 판정 결과를 반환한다. 미리보기와 실제 사격은 같은 부위와 확률을 사용한다.
- TurnManager: ACTIVE 행동만 허용하고 CRITICAL의 AP 회복·탈출 기회를 보존한다. 상태 변경을 구독해 승패와 적 행동을 정리한다.
- EnemyAIController: ACTIVE 적만 행동한다. ACTIVE/CRITICAL 아군을 기존 목표 선택 규칙으로 공격하며 기본 조준은 Body다.
- PlayerInputController: CRITICAL 아군 선택은 허용하되 이동·공격 입력을 거절하고 탈출 입력을 처리한다.
- UnitActionUI: 기존 메뉴에 Eject(AP 1)를 추가하고 상태를 표시한다. CRITICAL에서는 전투 버튼을 비활성화하고 Eject만 허용한다.
- BodyTargetUI/BattleDebugUI: 전체 HP 대신 각 부위 HP와 기체 상태를 표시한다. 파괴된 부위를 구분하고 사격 결과도 해당 부위 피해/HP와 상태로 설명한다.

기존 Tests와 Editor Scene Builder에서 전체 HP API를 사용하던 부분을 Body HP 또는 부위 상태 검사로 옮긴다.
오래된 전체 HP를 별도 호환 체력으로 계속 관리하지 않는다.
맵 크기·유닛/엄폐/장애물/골짜기 위치·카메라 설정·기체 movement speed 12f와 원본 PNG를 보존한다.
샘플 씬을 초기 배치로 재생성하지 않는다. 새 능력치를 저장하려고 사용자 배치를 덮어쓰지 않는다.

## 검증 범위

- 부위별 초기 HP와 단일 부위 피해, 초과 피해/중복 파괴 방지.
- 콕피트 명중률 35%, 엄폐 시 5%, 회피로 0%, 원거리 5 피해 두 번으로 파괴.
- 주요 부위 0/1/2개 파괴는 ACTIVE, 3개에서 한 번 판정, 4개에서 무조건 DESTROYED.
- 25% 판정의 24/25 경계, CRITICAL 추가 명중 재판정, 빗나감과 같은 공격의 이중 판정 방지.
- Body/Cockpit 파괴가 부위 개수보다 우선하며 확률 없이 DESTROYED.
- 근접은 Body에만 8 피해, 원거리는 선택한 부위에만 피해. 표시와 실제 명중률/AP 일치.
- CRITICAL의 이동/공격 차단, 클릭 선택과 Eject UI, AP 1 차감, AP 0 거절 및 다음 턴 탈출.
- ACTIVE의 선제 탈출, 탈출 중복 실행 거절, 탈출 후 공격/선택/행동/점유 제외.
- CRITICAL 재공격·그리드 점유 유지, 적 AI 행동 건너뛰기, 기체 상태 전환 중 이동 취소.
- 마지막 CRITICAL 아군의 탈출 기회, 전투 종료와 적 순차 행동 중단, 기존 카메라/선택/엄폐/골짜기 회귀.
- 원본 편집기가 열려 있으면 기존 검증용 Unity 프로젝트에 동일 Assets를 동기화해 EditMode/PlayMode 전체 검증을 실행한다.
  테스트는 사용자 배치와 속도를 고정값으로 확인하거나 수정하지 않는다.
