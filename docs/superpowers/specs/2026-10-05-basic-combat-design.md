# HP·AP·공격과 더미 적 설계

작성일: 2026-10-05  
상태: 구현·자동 검증·독립 검토 완료 — 실제 OS 마우스·IMGUI 시각 검사는 미실행

## 목적과 성공 기준

기존 3D 쿼터뷰 전투 스켈레톤에 HP, AP, 확률 공격, 행동하지 않는 더미 적 1체를 추가한다.
플레이어가 한 턴의 제한된 AP로 이동과 공격을 조합하고, 예상 명중률을 확인한 뒤
더미를 공격하여 처치할 수 있는 전투 테스트를 만든다.

기존 그리드 데이터, BFS 이동, 실제 이동 거리 기반 회피, 방향별 엄폐를 활용한다.
Unity 기본 Primitive와 현재 설치된 Input System·Test Framework를 사용하며
외부 에셋이나 패키지를 추가하지 않는다. 이번 문서는 기존 설계의 자유 반복 이동 규칙을
AP·턴 제한으로 확장하고, 공격·HP·사망을 제외했던 범위를 변경한다.

완료 기준은 AP에 따른 이동 범위, 칸별 AP 소모, 공격 미리보기와 확률 판정,
피해·사망·점유 해제, 턴 종료 후 AP 회복과 이동 회피 초기화가 테스트 Scene에서 작동하는 것이다.
더미는 적으로 구분하며 플레이어가 선택하여 이동시키거나 공격하게 할 수 없다.

## 확정한 초기 수치

| 항목 | 기본값 |
| --- | --- |
| 플레이어 최대·시작 HP | 20 |
| 더미 최대·시작 HP | 20 |
| 플레이어 최대·턴 시작 AP | 5 |
| 이동 비용 | 실제 도착한 한 칸마다 AP 1 |
| 공격 비용 | 시도 한 번마다 AP 3 |
| 공격력 | 5 |
| 기본 명중률 | 80% |
| 공격 사거리 | 그리드 좌표 기준 직선 거리 5칸 |
| 기존 한 번의 이동 범위 | 5칸 |
| Half / Full 엄폐 보너스 | 기존 값 15 / 30 |

HP·최대 AP·공격 비용·공격력·기본 명중률·사거리와 기존 이동 관련 수치는
Inspector에서 조절할 수 있게 한다. HP는 양수, AP·피해·사거리는 음수 불가,
공격 비용은 양수, 기본 명중률은 0~100으로 검증한다.
이동 비용은 이번 단계에서 한 칸당 1로 고정한다.

## 턴과 AP

플레이어 턴으로 시작하며 턴 번호의 초기값은 1이다. 더미는 행동하지 않으므로
‘턴 종료’는 다음 플레이어 턴을 바로 시작하고 턴 번호를 1 증가시킨다.
적 턴·적 AI·적 공격·자동 턴 종료는 구현하지 않는다.

턴 시작에는 살아 있는 플레이어의 AP를 최대값으로 회복하고 이동 칸 수와 이동 회피를 0으로 초기화한다.
HP, 현재 위치와 엄폐는 유지한다. AP가 0이어도 사용자가 턴 종료를 누를 때까지 현재 턴을 유지한다.
이동 회피는 턴 중에는 기존 규칙처럼 새 이동을 시작할 때 초기화하고,
이번 이동에서 실제 도착한 칸 수로 다시 계산한다. 공격은 이동 회피를 초기화하지 않는다.

이동 중에는 이동·선택 변경·공격·턴 종료를 차단한다.
턴 종료 시 공격 대상과 마지막 공격 결과를 해제하고, 선택된 플레이어의 이동 범위를 갱신한다.
더미 처치 후에는 처치 완료를 표시하고 전투 행동과 턴 진행을 막는다.
다시 시험하려면 Play를 재시작한다. 플레이어 사망도 전투 종료로 처리하되
이번 더미는 공격하지 않으므로 정상 플레이에서 플레이어 HP는 줄지 않는다.

## 이동 처리와 AP의 연결

경로 탐색 예산은 `min(기존 MovementRange, 남은 AP)`이다.
현재 균일 비용의 상하좌우 이동에는 BFS를 유지한다.
경로 길이가 예산을 초과하면 이동 요청을 거절하고 AP·회피·위치를 변경하지 않는다.
경로를 확정한 후 기존과 동일하게 이동 회피를 초기화하고 이동 범위 표시를 숨긴다.

각 셀에 도착하여 점유 이전에 성공할 때 AP 1을 소모하고,
도착 칸 수와 회피를 갱신한다. AP 소모와 점유 이전의 사전 조건을 함께 확인하여
AP만 소모되거나 AP 없이 셀을 옮기는 상태가 생기지 않게 한다.
이동 도중 경로가 막히거나 컴포넌트가 비활성화되면 마지막으로 점유한 셀 중심으로 복귀한다.
그때까지 도착한 칸의 AP만 소모하며, 미완료 구간에는 비용을 부과하지 않는다.

이동 후 남은 AP를 기준으로 범위를 다시 계산한다. 예를 들어 AP 5에서
2칸 이동하면 AP 3으로 공격 가능하고, 3칸 이동하면 AP 2로 공격할 수 없다.
이동 없이 공격하면 AP 2가 남아 최대 2칸 이동할 수 있다.

## 공격 판정

공격은 살아 있는 플레이어가 살아 있는 적을 대상으로만 할 수 있다.
자기 자신·아군·미등록 유닛·사망 유닛에 대한 요청, AP 부족,
이동 중 요청, 사거리 초과, 전투 종료 상태는 거절한다.
거절된 요청은 AP·HP와 난수 상태를 변경하지 않는다.

사거리는 공격자와 대상의 그리드 좌표를 사용하여
`sqrt((대상.x - 공격자.x)^2 + (대상.z - 공격자.z)^2)`로 계산한다.
셀 중심 간 직선 거리를 셀 크기로 나눈 값에 해당하며 단위는 칸이다.
공격 범위는 원형에 가까운 형태이고, 가로 3·세로 3은 약 4.24칸이므로 공격 가능하다.
가로 3·세로 4는 정확히 5칸으로 허용하며, 가로 4·세로 4는 약 5.66칸으로 거절한다.
실제 범위 판정은 좌표 차이의 제곱합과 사거리의 제곱을 비교하여 경계를 포함한다.
이동 경로 길이와 무관하며, 장애물 우회를 계산하지 않는다.
이번 단계에는 시야·탄도·중간 장애물 차단 검사가 없다.
따라서 사거리 안에서는 중간에 장애물이나 엄폐 Cube가 있어도 공격 가능하다.
Full 엄폐 역시 완전한 공격 차단이 아니라 명중률 감소로 동작한다.

최종 명중률은 다음과 같다.

`clamp(공격자의 기본 명중률 - 대상의 이동 회피 - 대상의 적용 방향 엄폐 보너스, 0, 100)`

엄폐 방향은 대상 셀에서 공격자 셀을 바라보는 방향이다.
두 좌표의 차이 중 절댓값이 큰 축을 선택하며, 두 축이 같으면 Z축(남·북)을 우선한다.
Z축 양수는 North, 음수는 South, X축 양수는 East, 음수는 West이다.
예를 들어 대상보다 북쪽의 공격자는 대상의 North 엄폐 보너스를 적용받는다.
같은 셀의 유닛은 정상 점유 규칙상 존재할 수 없으며, 같은 좌표의 공격 요청은 거절한다.

공격 버튼을 누르면 최신 AP·위치·대상 상태로 다시 검증하고 명중률을 재계산한다.
유효한 요청은 AP 3을 한 번 소모한 뒤 0~99의 정수 난수를 한 번 뽑는다.
난수가 최종 명중률보다 작으면 명중한다. 0%는 항상 빗나가고 100%는 항상 명중한다.
명중 시 고정 공격력 5만큼 피해를 주며, 빗나가면 피해는 0이다.
명중 여부와 무관하게 AP는 소모한다. 회피·엄폐 보너스는 HP에 직접 영향을 주지 않는다.

## HP·사망·더미

HP는 0~최대 HP 범위로 유지하며 음수 피해는 허용하지 않는다.
피해 적용 후 HP가 0이 되면 사망을 한 번만 처리한다.
사망 유닛은 이동·선택·공격 대상에서 제외하고, 그리드 점유를 즉시 해제하며,
표시와 Collider를 제거하여 클릭되지 않게 한다.
Unity의 지연 Destroy와 무관하게 전투 상태와 점유 해제는 사망 처리 시 확정한다.

더미는 빨간 Capsule로 만들고, 기존 장애물과 겹치지 않는 셀 (3,3)에 배치한다.
기존 플레이어의 시작 셀 (1,1)에서 거리가 약 2.83칸이므로 바로 공격을 시험할 수 있다.
더미 셀은 기존 배치에 따라 North=Full, South=Half 엄폐를 갖는다.
플레이어가 (1,1)에 있을 때 좌표 차이는 (-2,-2)이므로 South 엄폐를 적용하고,
더미 이동 회피가 0인 초기 상태에서는 예상 명중률이 65%이다.
더미는 점유 장애물이므로 살아 있는 동안 그 셀을 통과하거나 도착할 수 없다.

## 책임 분리

| BattleUnit | 팀(Player / Enemy), 현재 그리드 좌표, 이동·회피·HP·AP 컴포넌트 연결. 전투 계산 자체는 담당하지 않는다. |
| UnitHealth | 최대·현재 HP, 피해 적용과 사망 상태. 사망을 알리며 중복 처리를 방지한다. |
| UnitActionPoints | 최대·현재 AP, 비용 검증·소모·턴 시작 회복. |

| CombatSystem | 유효 대상·AP·사거리 검증, 방향별 엄폐 조회, 미리보기, 난수 판정·피해·공격 결과. |
| TurnManager | 현재 턴 번호, 행동 허용·전투 종료 상태, 턴 종료와 플레이어 AP·회피 초기화. |
| UnitMovement / Pathfinder | AP를 반영한 범위·경로와 실제 셀 도착 시 비용 연결. 이동 표현·점유 관리는 기존 책임을 유지한다. |
| BattleSceneController | 기존 초기화 순서에 HP·AP·전투·턴 연결을 추가하고 사망 시 점유 해제와 전투 종료를 연결한다. |
| PlayerInputController | 플레이어 선택, 빈 칸 이동, 적 클릭으로 대상 지정. 공격·턴 종료 요청을 담당 시스템에 전달한다. |

| BattleTestSceneBuilder | 플레이어 설정·빨간 더미·전투 관련 컴포넌트·참조를 포함한 Scene과 Prefab 생성. |

일반적인 직접 참조와 필요한 최소 알림을 사용한다.
범용 능력 시스템, 이벤트 버스, 복잡한 상태 머신, 새 DI 프레임워크는 추가하지 않는다.
난수의 입력과 순수 명중 계산은 테스트에서 결과를 고정할 수 있도록 분리한다.
화면에서 보여 주는 미리보기와 실제 공격은 같은 계산 경로를 사용한다.

## 조작과 화면

기존 BattleTest Scene을 확장하며 SampleScene과 Build Settings는 변경하지 않는다.
플레이어를 클릭하면 선택하고, 이동 가능한 빈 칸을 클릭하면 이동한다.
더미를 클릭하면 플레이어 선택을 유지하고 공격 대상으로 지정한다.
플레이어가 미선택이면 먼저 플레이어를 선택하도록 안내한다.
엄폐·장애물 클릭은 기존처럼 무시한다.

기존 왼쪽 패널을 확장하여 턴 번호, 플레이어 HP·AP, 좌표·회피·네 방향 엄폐,
대상 HP·거리·적용 엄폐 방향·예상 명중률, 공격 버튼, 턴 종료 버튼을 표시한다.
사거리 밖·AP 부족 등 공격 불가 이유도 표시하고 버튼을 비활성화한다.
마지막 공격 결과는 명중/빗나감, 피해량과 남은 대상 HP를 표시한다.
공격 모션·총알·이펙트는 이번 범위에 포함하지 않는다.

이동 시작, 플레이어 선택 변경, 턴 변경, 대상 사망 시 대상 미리보기를 해제한다.
공격 직후에는 대상이 살아 있으면 미리보기를 갱신한다.
사망 시 참조를 해제하되 마지막 공격 결과와 처치 완료는 값 데이터로 유지한다.
패널과 클릭 차단 영역을 함께 갱신하여 UI 클릭이 맵 이동으로 전달되지 않게 한다.
작은 Game View에서도 기존 배율 방식과 카메라 영역을 고려하여 버튼이 표시되도록 한다.

## 검증 범위

Edit Mode에서는 규칙의 경계값과 상태 변경을 검증한다.

- HP 초기화, 피해, 0으로 제한, 중복 사망 방지.
- AP 초기화·회복, 정확한 소모, 부족 시 변화 없음.
- 이동 예산과 경로 제한, AP 0/2/3/5의 차이.
- 직선 사거리: (5,0)·(3,4) 허용, (6,0)·(4,4) 거절, (3,3) 허용.
- 팀·생존·등록·동일 좌표 검증.
- 동서남북과 대각선 동률의 엄폐 방향, Half/Full 적용, 이동 회피와 합산.
- 명중률의 0·100 제한과 난수 경계(명중률보다 작은 값만 명중).
- 명중·빗나감의 동일 AP 소모, 거절된 요청의 AP·HP·난수 호출 없음.
- 턴 시작 AP·회피 초기화, 위치·HP 유지, 이동 중·전투 종료 후 턴 종료 거절.

Play Mode에서는 실제 컴포넌트 연결과 저장된 Scene을 검증한다.

- 클릭 선택·이동·적 대상 지정과 AP 기반 범위 갱신.
- 2칸 이동 후 공격, 공격 후 2칸 이동, AP 부족 시 공격 차단.
- 이동 도중 차단·비활성화 시 완료한 칸만 AP 소모.
- 이동 중 공격·턴 종료·재입력 차단.
- 더미 선택으로 플레이어 조작권이 넘어가지 않음.
- 미리보기와 공격 판정 일치, 고정 난수로 명중·빗나감 재현.
- 더미 사망 즉시 점유 해제·대상 참조 해제·전투 종료와 중복 공격 차단.
- 턴 종료 후 AP 5·회피 0, HP·위치 유지와 범위 갱신.
- 기존 이동·엄폐·입력 회귀 검증, 정상 Scene 초기화 시 오류·경고 없음.

기존 테스트는 자유 반복 이동이 아니라 새 AP·턴 규칙에 맞게 조정하되,
경로·점유·입력의 기존 보장을 유지한다. 실제 OS 마우스와 IMGUI 화면을 직접 확인하지 못하면
자동 테스트나 카메라 렌더 결과와 구분하여 전달한다.

## 제외 범위와 전달물

적 AI·적 공격·적 턴, 무기·탄약·재장전, 치명타·방어력, 시야 차단,
부위 파괴, 애니메이션·이펙트, 승패 보상, 재시작 버튼, 저장·불러오기는 제외한다.
험지 비용·Dijkstra 변경, 회전 그리드·동적 엄폐·동시 이동도 추가하지 않는다.

구현 시 변경된 Scene·Prefab·코드, 실행된 테스트 결과,
HP·AP·공격 수치의 조절 위치와 조작 방법을 기존 한국어 가이드에 반영한다.
이번 폴더는 Git 저장소가 아니므로 문서를 파일로 보존하며 커밋하지 않는다.

## 설계 검토

사용자는 대각선 공격 범위 설명 후 사거리를 그리드 좌표 기준 직선 거리로 변경하도록 요청했다.
이동은 기존 상하좌우 BFS와 한 칸당 AP 1 규칙을 유지한다.
사용자는 턴 방식, AP 5, 한 칸당 이동 AP 1, 공격 AP 3,
확률 공격과 초기 전투 수치, 책임 분리·조작·검증 범위를 승인하고 문서 작성을 요청했다.
작성 후 수치·턴·AP·회피·방향·사망·조작·테스트의 일관성과 미정 항목을 자체 검토했다.
사용자는 수정된 설계를 기준으로 구현 계획 작성을 요청했다.
구현 계획은 `docs/superpowers/plans/2026-10-05-basic-combat.md`에 작성했다.
사용자는 계획 검토 후 이 세션에서 직접 구현하고 마지막에 독립 검토하는 방식을 승인했다.
최종 자동 검증은 EditMode 80개, PlayMode 36개가 통과했다.
독립 검토의 중요 결함 두 건은 실패 테스트로 재현한 뒤 수정했다.
Inspector 비활성화 관련 경미한 예외 두 건과 검증 한계는
`Artifacts/combat-code-review.md` 및 한국어 가이드에 기록했다.
