# MechaData 기본 탐지 거리 연동

## 목적과 확정 범위

기체별 기본 탐지 거리를 MechaData에 정의하고, BattleUnit이 전투 시작 시 UnitVision에 적용한다. 현재 최종 탐지 거리는 MechaData의 기본 탐지 거리와 같다. 기존 탐지·전장의 안개·적 AI·공격 대상 제한은 UnitVision을 읽는 기존 경로를 유지한다.

추가부품으로 탐지 거리를 늘리는 방향을 고려하지만, 이번에는 부품 데이터·슬롯·보너스 필드·합산기·패시브 시스템을 만들지 않는다. 머리 파괴 보정, 파일럿 보정, 탐지 거리 UI 개편도 제외한다.

## 선택한 구조와 대안

- 선택: MechaData → BattleUnit.Initialize → UnitVision.Configure → 기존 VisibilitySystem. 기체 기본 성능의 출처를 통일하고 현재 책임 분리를 유지한다.
- 대안: UnitVision의 Inspector에서 유닛마다 직접 관리. 현재 방식이지만 같은 기종의 성능을 일괄 관리하기 어렵다.
- 대안: 탐지 거리 전용 능력치·추가부품 시스템을 함께 구현. 아직 요청하지 않은 장착 구조와 합산 정책이 필요하므로 보류한다.

## 동작 규칙

- `MechaData.detectionRange`: 정수 칸 수, 기본값10, 최솟값0. 공개 읽기 속성은 `DetectionRange`.
- 0은 탐지 반경0을 의미한다. 제한 미설정이나 기본값 대체로 해석하지 않는다. 기존 원형 범위 판정에 따라 자신의 칸만 범위에 포함된다.
- Inspector 한글 표시는 `기본 탐지 거리 (칸)`으로 한다. 음수는 IsValid에서 거부하며 OnValidate에서는0으로 보정한다.
- MechaData가 있으면 전투 시작 시 기존 UnitVision 개별 값보다 MechaData 값이 우선한다. UnitVision이 없으면 기존처럼 생성한다.
- MechaData가 없으면 기존 UnitVision 설정을 보존한다. UnitVision도 없으면 기존 기본값10을 사용한다.
- 초기화 완료 후에는 공유 MechaData를 매 프레임 읽거나 자동 재적용하지 않는다. 데이터 변경은 전투 재시작 시 반영한다.
- 같은 그리드로 Initialize를 재호출하거나 턴이 바뀌어도 탐지 거리를 다시 덮어쓰지 않는다. 기존 UnitVision.Configure와 변경 알림은 유지한다.
- 같은 MechaData를 참조하는 여러 유닛의 UnitVision 값은 독립적이며, UnitVision 변경이 공유 에셋을 수정하지 않는다.
- 원형 거리·경계 포함·건물 시야 차단·공유 시야·발견 해제·탐험 기록 규칙은 바꾸지 않는다.

## 보존 및 검증

저장 씬·기체 에셋·프리팹을 일괄 수정하거나 다시 저장하지 않는다. 기존 MechaData에 새 필드가 없는 경우 기본값10으로 읽히는지 복제본에서 검증한다. 사용자 설정인 이동 속도·카메라 속도·zoomSpeed·Shadow Max Distance·엄폐 배율·맵 배치는 그대로 둔다. Git 작업 없이 기존 Unity 테스트 복제본을 사용한다.

데이터 저장·기존 에셋 호환, 초기화·독립성, 최초 발견·안개·AI 동작을 실제 테스트로 검증한다. 계획 작성만 요청받은 상태이므로 이 문서 작성으로 제품 코드나 데이터를 변경하지 않는다.
