# 파일럿 패시브 인터페이스 설계

## 목적과 범위

여러 파일럿 패시브를 같은 방식으로 평가할 수 있는 C# 확장 구조를 준비한다. 이번 범위는 UI가 아니라 코드 인터페이스다.

실제 파일럿 데이터, 습득 목록, 구체적인 패시브 에셋, 전투 효과 연결은 구현하지 않는다. 현재 공격 AP와 명중률은 변경되지 않는다.

## 구조

### IPilotAttackPassive

각 패시브는 다음 계약을 구현한다.

- `Id`: 패시브를 구분하는 고유 문자열.
- `CanApply(PilotAttackContext context)`: 현재 공격 조건에서 적용 가능한지 판단한다.
- `GetModifiers(PilotAttackContext context)`: 적용할 보정값을 반환한다. 공유 무기·기체 데이터나 현재 전투 상태를 수정하지 않는다.

인터페이스는 일반 C# 클래스나 추후 ScriptableObject 모두에서 구현할 수 있다. 이번에는 별도의 ScriptableObject 기반 클래스는 만들지 않는다.

### PilotAttackContext

사용자 확인에 따라 공격 시점 전용으로 명시한다. 턴 시작이나 피격 이벤트는 향후 별도의 Context와 계약으로 추가한다.

공격 관련 판단에 필요한 값만 읽기 전용으로 전달한다.

- 공격자와 대상 유닛: 선택 사항. 기체 데이터는 공격자를 통해 조회한다. 아직 기체 역할 분류는 추가하지 않는다.
- 무기 데이터: 필수. 근접/원거리 종류는 무기에서 읽는다.
- 한손/양손 사용 방식.
- 조준 부위.
- 대상까지의 그리드 거리.
- 이번에 전달받은 이동 칸 수. 누적 이동 규칙을 새로 만들지 않는다.

대상을 정하기 전에는 대상 null, 거리 0과 Whole 부위를 사용할 수 있다. 대상 유무가 필요한 패시브는 HasTarget을 확인한다. 이동량은 호출자가 전달하며, 누적 이동 규칙을 정의하지 않는다.

### PilotAttackModifiers

첫 확장 지점은 두 가지로 제한한다.

- 공격 AP 감소량: 0 이상의 정수.
- 명중률 배율: 유한한 양수. 기본값은 1.

보정이 없는 기본값은 AP 감소 0, 명중률 배율 1이다. 피해량, 치명타, 성장, 재사용 시간은 추가하지 않는다.

### PilotAttackPassiveEvaluator

패시브 목록과 조건을 받아, 조건을 만족한 패시브의 ID와 보정값을 순서대로 반환한다.

- 여러 패시브를 입력할 수 있다.
- null 목록은 빈 결과, null 항목은 건너뛴다.
- 빈 ID와 중복 ID는 설정 오류로 처리한다.
- 결과는 읽기 전용 목록으로 제공한다.
- AP 감소끼리 최대값을 취할지, 명중률 배율을 곱할지 등의 최종 중첩 계산은 이번 범위에 포함하지 않는다.

이 구조에서는 AP 감소 패시브와 특정 무기 명중률 패시브가 함께 조건을 만족하면 각각의 결과를 얻는다. 실제 최종 AP·명중률 계산은 나중에 공통 전투 계산 경로에 연결한다.

## 기존 코드와의 관계

새 파일은 `Assets/_Game/Scripts/Unit/` 아래에 둔다. 기존 `WeaponData`, `MechaData`, `UnitCombat`, `CombatSystem`은 수정하지 않는다.

파일럿별 패시브 소유 목록과 전투 중 적용 책임도 이번에 추가하지 않는다. 기체 역할, 파일럿 능력치, 경험치 같은 시스템을 미리 구현하지 않는다.

## 검증

EditMode 테스트로 다음을 확인한다.

1. 보정의 기본값이 중립이다.
2. 조건을 만족한 패시브만 반환하며 여러 결과의 입력 순서를 보존한다.
3. 빈 목록과 null 항목을 처리한다.
4. 잘못된 ID, 중복 ID, 음수 AP 감소량 및 유효하지 않은 배율을 거부한다.
5. 컨텍스트의 필수 무기 및 거리·이동 칸 수를 검증한다.

실제 패시브 대신 테스트용 구현으로 계약을 검증한다. 전체 EditMode 테스트를 실행해 기존 코드와 함께 컴파일되고 기존 검증이 유지되는지 확인한다. 씬, 모델 배치, 이동 속도, 줌, 그림자 설정은 수정하지 않는다.
