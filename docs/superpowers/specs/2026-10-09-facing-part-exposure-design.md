# 이동 후 방향 선택과 부위 노출 설계

## 목적과 승인된 규칙

플레이어가 이동 후 기체의 방향을 정해 적에게 노출되는 부위를 선택하게 한다.
기체의 로컬 +Z를 정면으로 사용한다. 왼쪽에서 공격받으면 왼팔·왼다리는 맞히기
쉬워지고 오른팔·오른다리는 맞히기 어려워진다. 오른쪽에서는 반대로 적용한다.

사용자가 승인한 규칙:

- 이동 완료 → 동·서·남·북 방향 선택 → 확정.
- 방향 선택에는 AP가 들지 않는다.
- 선택을 기다리는 동안 다른 행동과 턴 종료를 막는다.
- 부위 노출 판정은 대상 기체 기준 8방향이다.
- 몸통·머리·콕피트의 기존 조준 배율은 유지한다.
- 방향 보정은 기존 부위·엄폐 보정과 곱한다.

| 공격이 들어오는 상대 방향 | 왼팔·왼다리 | 오른팔·오른다리 |
|---|---:|---:|
| 정면 / 후면 | 1 | 1 |
| 왼쪽 | 1.2 | 0.7 |
| 오른쪽 | 0.7 | 1.2 |
| 왼쪽 앞 / 왼쪽 뒤 | 1.1 | 0.85 |
| 오른쪽 앞 / 오른쪽 뒤 | 0.85 | 1.1 |

몸통·머리·콕피트의 노출 배율은 모든 방향에서 1이다.
원거리 공격에 적용하며, 몸통을 공격하는 현재 근접 공격의 노출 배율은 1로 유지한다.

## 현재 구조와 변경 이유

현재 `UnitMovement`는 다음 칸으로 이동하기 전에 `Visual`을 부드럽게 회전시킨다.
이동 속도는 12f이고 회전 속도는 초당 360도다. 방향이 게임 로직 데이터로
저장되어 있지 않으므로, 시각 회전값만으로 명중률을 계산하면 회전 애니메이션의
중간 각도나 모델의 유무가 전투 판정에 영향을 줄 수 있다.

확정된 기체 방향을 `BattleUnit`의 전투 데이터로 관리한다. 이동·회전 표현은
`UnitMovement`, 플레이어의 선택 흐름은 `PlayerInputController`와 기존 행동 UI,
전투 전체의 행동 잠금은 `TurnManager`가 담당한다. 상대 방향과 배율 산출은
순수 계산 함수로 분리한다.

## 방향 데이터와 회전 표현

- 방향은 월드 좌표의 북(+Z), 동(+X), 남(-Z), 서(-X) 네 값으로 관리한다.
- 초기 방향은 기존 Visual의 월드 정면을 가장 가까운 4방향으로 정규화한다.
  Visual이 없으면 유닛 루트 정면을 사용한다. 정확한 45도 경계는 시계 방향으로 정한다.
- 루트 Transform과 선택용 Collider를 회전시키지 않는다.
- Visual이 없는 적 더미도 논리 방향을 가진다. 시각 모델이 없어도 판정은 같다.
- 이동 중에는 다음 칸 방향으로 회전한 뒤 전진하는 기존 동작을 유지한다.
- 칸에 도착하면 해당 이동 방향을 논리 방향으로 기록한다.
- 공격 시 대상을 향해 자동으로 방향을 바꾸지 않는다. 플레이어가 확정한 방향을 유지한다.
- 턴이 바뀌어도 방향을 초기화하지 않는다.

실수 각도를 전투 데이터로 저장하는 방식 대신 4방향 데이터를 사용한다.
사용자가 선택할 수 있는 방향과 전투 판정이 일치하며, 애니메이션과 판정을 분리할 수 있다.

## 플레이어의 방향 선택 흐름

1. 기존 Move 버튼과 그리드 클릭으로 이동한다.
2. 요청한 목적지에 정상 도착한 아군은 방향 확정 대기 상태에 들어간다.
3. 이동한 유닛 옆의 기존 행동 패널에 북·동·남·서 버튼과 확정 버튼을 표시한다.
4. 기본 선택값은 마지막 이동 방향이다. 방향 버튼은 선택 표시만 바꾼다.
5. 확정을 누르면 선택한 방향으로 Visual을 부드럽게 회전시킨다.
6. 회전 완료 시 논리 방향을 확정하고 대기 상태를 해제한다. 기존 행동 패널로 돌아간다.

방향 선택 패널은 일반 Move/Attack/Eject 패널을 대신 표시한다.
카메라의 회전·이동과 관계없이 버튼의 북·동·남·서는 월드 방향을 의미한다.
WASD 카메라 이동과 Q/E 카메라 회전은 기존대로 사용한다.

방향 버튼을 클릭할 때마다 모델을 돌리는 미리보기 대신, 확정 시 한 번 회전한다.
이렇게 하면 선택 중에는 확정 방향과 모델 방향이 유지되고 불필요한 중간 회전을 피한다.

### 잠금과 예외 처리

- 대기 및 확정 회전 중에는 이동·공격·긴급탈출·다른 유닛 선택·턴 종료를 막는다.
- 입력 UI뿐 아니라 직접 호출되는 행동 API와 `TurnManager.TryEndTurn`도 잠금을 검사한다.
- AP가 0이어도 방향 선택·확정은 가능하다. 회전으로 AP나 기동 회피가 증가하지 않는다.
- 방향 선택 중 허공이나 다른 유닛을 클릭해도 대기 유닛 선택을 유지한다.
- 방향 선택 중 ESC는 버튼으로 고른 후보를 취소하고 마지막 이동 방향을 그대로
  확정한 뒤 선택을 해제한다. 잠금을 남기거나 추가 회전을 제공하지 않는다.
- 확정 회전 중 ESC는 무시하고 회전 완료를 기다린다.
- 이동 중 ESC로 기존처럼 선택을 해제한 경우에도 정상 도착 시 도착한 유닛을
  다시 선택하고 방향 패널을 표시한다. 완료 감지는 선택된 유닛의 Update에만 의존하지 않는다.
- 이동 취소나 경로 차단으로 목적지에 도착하지 못하면 방향 패널을 열지 않는다.
  마지막으로 완전히 도착한 칸의 방향으로 논리·시각 방향을 맞춘다.
- Critical 진입, 파괴, 탈출, 비활성화, 전투 종료는 대기와 회전을 정리한다.
  정리 후 전투의 행동 잠금이 남지 않아야 한다.

ESC 동작과 확정 전 미리보기 생략은 기존 입력과 잠금 해제를 일관되게 유지하기
위한 이번 문서의 구체적인 동작 선택이다.

## 적의 방향

적도 같은 방향 데이터와 부위 노출 규칙을 사용한다. 적에게 방향 선택 UI는 열지 않는다.
적이 이동하면 마지막으로 완료한 이동 방향을 자동 확정하고 다음 AI 행동을 수행한다.
이동하지 않으면 기존 방향을 유지한다. 엄폐 탐색이나 최적 방향 선택 AI는 추가하지 않는다.

## 8방향 상대 판정

현재 `CombatMath.GetIncomingDirection`은 대상에서 공격자를 바라보는 월드 방향을
45도 구역으로 나눈다. 이 구역을 대상의 확정된 4방향에 맞춰 회전시켜 상대 방향을 얻는다.

상대 방향 순서:

```text
정면 → 오른쪽 앞 → 오른쪽 → 오른쪽 뒤
→ 후면 → 왼쪽 뒤 → 왼쪽 → 왼쪽 앞
```

각 구역은 중심으로부터 ±22.5도 범위다. 경계는 기존 함수처럼 시계 방향 구역에 포함한다.
기존 `CoverDirection` enum의 정수 값은 각도 순서가 아니므로, enum 값을 그대로
빼서 상대 방향을 계산하지 않는다. 명시적인 시계 방향 순서를 사용한다.

예:

- 북향 기체 + 서쪽 공격자 → 왼쪽.
- 북향 기체 + 북서쪽 공격자 → 왼쪽 앞.
- 동향 기체 + 북쪽 공격자 → 왼쪽.
- 남향 기체 + 서쪽 공격자 → 오른쪽.

## 명중률 계산과 엄폐의 관계

```text
최종 명중률
= max(0, 기본 명중률 − 대상 기동 회피)
  × 공격자 머리 손상 배율
  × 조준 부위 배율
  × 부위 노출 배율
  × 엄폐 배율
```

전체 계산 후 0~100%로 제한하고 기존 방식으로 정수 반올림한다.
노출 배율을 곱하기 전에 중간 결과를 반올림하거나 100%로 제한하지 않는다.

현재 부위 배율: 몸통 1, 머리 0.8, 팔·다리 0.9, 콕피트 0.45.
현재 엄폐 배율: None 1, Half 0.75, Full 0.5.

예: 기본 명중률 80, 회피 0, 공격자 머리 정상, 북향 대상의 왼쪽에서 공격.

| 조준과 엄폐 | 계산 | 결과 |
|---|---|---:|
| 왼팔, None | 80 × 0.9 × 1.2 | 86% |
| 오른팔, None | 80 × 0.9 × 0.7 | 50% |
| 왼팔, Full | 80 × 0.9 × 1.2 × 0.5 | 43% |
| 오른팔, Full | 80 × 0.9 × 0.7 × 0.5 | 25% |

엄폐는 여전히 대상 칸에서 공격자를 바라보는 월드 방향으로 판정한다.
기체를 회전해도 그 칸의 엄폐 종류나 적용 방향은 변하지 않는다.
건물의 사선 차단, 골짜기 통과 사격, 사거리, 피해량, 공격 AP는 기존 규칙을 유지한다.

공격 미리보기와 실제 공격은 동일한 확정 방향과 배율 계산을 사용한다.
미리보기 데이터에 상대 공격 방향과 노출 배율을 포함하고, 디버깅창에서 확인할 수 있게 한다.
부위 선택 UI의 명중률에도 같은 계산을 적용한다.

## 검증 범위

### 계산 검증

- 대상의 4방향 각각에서 8방향 공격과 7개 조준 부위의 노출 배율을 검증한다.
- 동서남북 회전에 따른 상대 좌우 변환과 22.5도 경계를 검증한다.
- 기존 부위·엄폐·머리 손상·기동 회피와의 곱, 마지막 반올림, 0~100 제한을 검증한다.
- 몸통·머리·콕피트, 근접 공격의 기존 결과가 유지되는지 확인한다.
- 대상 방향만 바꿔도 월드 엄폐 배율과 건물 차단 결과는 같아야 한다.

### 실제 전투 검증

- 정상 이동 후 패널이 열리고, 4방향 모두 선택·확정할 수 있어야 한다.
- AP 0에서도 확정 가능하며 회전에 AP가 들지 않아야 한다.
- 대기 및 확정 회전 중 다른 행동과 직접 턴 종료 호출이 차단되어야 한다.
- 정상 확정과 ESC 기본 방향 확정 후 잠금이 해제되어야 한다.
- 이동 중 선택 해제, 이동 취소, 차단, Critical, 파괴·탈출·비활성화에 잠금이 남지 않아야 한다.
- 적은 방향 패널 없이 행동을 이어가며 아군과 같은 부위 노출 계산을 사용해야 한다.
- Visual과 논리 방향이 완료 시 일치하고, 루트와 Collider는 회전하지 않아야 한다.
- 세 저장 전투 씬에서 기존 선택·이동·공격·턴 흐름과 방향 기능을 확인한다.

사용자가 조정한 이동속도 12f, 라이플의 손잡이·위치·크기, 맵 크기, 유닛·장애물 배치,
카메라 이동속도는 수정하거나 고정 수치로 검증하지 않는다. 테스트는 원본 에디터와
분리된 기존 검증 프로젝트에서 순차 실행하고 씬·모델·무기 프리팹의 변경 여부를 확인한다.

## 이번 범위에 포함하지 않는 것

제자리에서 자유롭게 방향을 바꾸는 별도 행동, 방향별 피해량·장갑·엄폐 변경,
몸통·머리·콕피트의 방향별 추가 배율, 근접 부위 조준, 최적 방향을 선택하는 적 AI,
애니메이션 리깅, 무기·파일럿·저장 시스템은 추가하지 않는다.
