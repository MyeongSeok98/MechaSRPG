# 턴 누적 이동 AP와 기체별 이동 효율

승인 범위: B 방식. MechaData.movementCellsPerAP를 기체별로 직접 지정하고 첫 BattleUnit 초기화 시 복사한다. 기본 이동 효율과 최종 GetMovementCellsPerAP 함수를 분리하여 미래 부품 보정을 이 지점에 연결한다. 부품 시스템 자체는 만들지 않는다.

효율이 일정할 때 누적 이동 AP는 ceil(턴 이동 칸/효율)이다. 각 칸에 도착할 때 새로 필요한 정수 AP만 차감한다. 먼저 지불한 AP의 남은 부분은 해당 자기 턴 동안 유지하며 이동 명령 분할·공격·재장전·선택 해제로 초기화하지 않는다. AP0이라도 지불한 여유분으로 한 칸을 완주할 수 있으면 이동 가능하다. 다음 자기 턴 시작에만 새 AP와 함께 초기화한다. 턴 종료 일괄 청구가 아니다.

계산은 남은 선불 AP 비율을 기록하는 순수 MovementCostLedger와 UnitMovement 연결로 나눈다. 효율 변경 전 이동 비용은 보존하고, 다음 칸은 1/현재 효율만큼 비용을 사용한다. 다리 하나 파괴 시 최종 효율×0.5, 둘 다 파괴 시0/이동 불가. 근접·사격 AP 등은 별도이며 이동 여유를 소모하지 않는다. 큰/작은 유한 양수 효율에서도 예외/정수 오버플로/첫 이동 무료 오류가 없어야 한다. 부동소수점 경계 오차는 작은 허용 오차로 처리하되 선불0/AP0일 때 양수 비용을 무료로 취급하지 않는다.

MechaData가 있는 기체는 기존 movementRange 고정 상한을 사용하지 않고 AP/선불 여유로 범위를 계산한다. MechaData가 없는 이전 유닛은 효율1과 기존 명령당 범위·다리 범위 제한을 호환한다. 기존 에셋 값을 자동 변경하지 않는다.

한 칸 이동 확정 전에 비용/점유 가능성을 재검증하고, Grid 위치 변경 알림 전에 해당 칸 비용을 확정한다. 부분 애니메이션 중 취소·장애물 추가·경계사격 중단은 도착한 칸까지만 비용을 낸다. 회전/선택/재초기화/컴포넌트 활성화로 선불 여유를 복구하거나 삭제하지 않는다. 이동 애니메이션 속도12f는 변경하지 않는다.

이동 가능 범위/BFS 경로·플레이어 Move 가용성·예상 이동 AP·AI 이동 후 공격 예산은 공통 비용 규칙을 사용한다. 현재 지형은 균일 비용이므로 BFS를 유지한다. AI는 사격 AP를 남기고 감당 가능한 경로를 고르며 기존 기본 행동 정책은 유지한다. 전투 디버그 표시는 칸당1AP 문구를 제거한다. 기존 UnitMobility의 명령별 이동/회피 기록은 유지하고 새 턴 이동 장부와 분리한다.
