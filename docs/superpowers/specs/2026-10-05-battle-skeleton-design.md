# 전투 스켈레톤 설계

작성일: 2026-10-05
상태: 구현 및 자동 검증 완료 — 직접 OS 마우스·UI 시각 검사는 미실행

## 목적과 성공 기준

Unity의 3D 쿼터뷰 전투 공간에서 그리드 이동, 이동 거리 기반 기동 회피,
방향별 엄폐를 검증한다. 최종 방향은 흙먼지 나는 육상 메카 전술전이며,
이번 결과물의 목적은 이동 감각과 엄폐 위치 선택의 이해 가능성을 확인하는 것이다.

Unity 기본 Cube와 Capsule을 사용한다. 외부 에셋이나 새 패키지를 추가하지 않는다.
기존 프로젝트는 Unity 6000.5.5f1의 URP 기본 프로젝트이고 게임 로직은 없다.
새 Input System이 이미 설치되어 활성화되어 있으므로 마우스 입력에 이를 사용한다.
기본 SampleScene을 보존하고 별도 테스트 Scene을 만든다.

완료 조건은 Play 시 그리드 표시, 유닛 선택, 이동 가능 범위 표시,
경로를 따른 이동, 장애물·점유 차단, 이동 회피 갱신, 방향별 엄폐 표시,
이동 회피와 엄폐의 별도 관리가 작동하고 Console에 오류가 없는 것이다.

## 확정한 공간 규칙

- XZ 평면의 정사각형 그리드. 기본 폭 10, 높이 10, 셀 크기 2m.
- GridManager의 위치를 그리드 남서쪽 바깥 모서리로 사용한다.
  셀 (x,z)의 중심은 원점 + ((x+0.5)*셀 크기, 0, (z+0.5)*셀 크기)이다.
- 그리드 자체의 회전과 비균일 스케일은 지원하지 않는다.
- North는 월드 +Z, East는 +X, South는 -Z, West는 -X이다.
- 이동은 상하좌우만 허용한다. 한 칸 이동 비용은 1이며 대각선 이동은 없다.
- MovementRange 기본값은 5. 장애물을 고려한 실제 최단 경로 길이에 적용한다.
- 시작 셀은 범위 계산의 기준이지만 이동 목적지로 표시하지 않는다.
- 장애물과 다른 유닛의 점유 셀은 통과하거나 목적지로 선택할 수 없다.
- 턴 제한 없이 반복 이동할 수 있다. 매 이동의 거리는 새로 기록한다.

## 구조와 데이터

Assets/_Game/Scripts 아래 Grid, Unit, Cover, Input, Presentation, Setup 폴더를 둔다.
Prefabs, Materials, Scenes 폴더도 Assets/_Game 아래에 둔다.
과도한 인터페이스, 추상 클래스, 이벤트 버스, DI는 사용하지 않는다.

| 클래스 | 책임과 주요 의존성 |
| --- | --- |
| GridCell | 일반 C# 데이터. 그리드 좌표, 월드 중심, Walkable, OccupyingUnit, 방향별 CoverType을 보관한다. Occupied는 OccupyingUnit으로부터 계산한다. |
| GridManager | 셀 생성, 좌표 변환, 셀 조회, 장애물 등록, 유닛 등록과 점유 변경. 다른 시스템의 공간 데이터 기준이다. |
| Pathfinder | 일반 C# 로직. GridManager와 유닛을 받아 BFS로 도달 가능 셀과 경로를 구한다. |
| BattleUnit | MovementRange, 시작 좌표와 현재 좌표, UnitMovement와 UnitMobility 연결. MovementEvasion은 UnitMobility 값을 조회하여 제공한다. |
| UnitMovement | 경로 검증, 이동 중 상태, 경로를 따른 부드러운 이동, 셀 도착 시 점유 변경. GridManager와 BattleUnit을 사용한다. |
| UnitMobility | 실제 이동 칸 수와 MovementEvasion의 단일 관리 지점. 이동 시작 초기화, 셀 도착 갱신, 향후 턴 초기화 메서드를 제공한다. |
| CoverObject | Half 또는 Full 설정과 Cube의 BoxCollider를 제공한다. |
| GridObstacle | 엄폐가 없는 일반 Cube 장애물을 명시적으로 등록한다. 바닥과 장식물을 장애물에서 구분한다. |
| CoverSystem | 등록한 CoverObject의 점유 영역으로부터 인접 셀의 방향별 엄폐를 계산한다. Half/Full 보너스를 각각 기본 15/30으로 관리한다. |
| PlayerInputController | 마우스 선택과 셀 클릭. 이동 중 입력을 차단하고 UnitMovement에 이동을 요청한다. |
| GridVisualizer | 그리드 선, 도달 가능 셀 표시, 선택 표시. 게임 규칙을 변경하지 않는다. |
| BattleDebugUI | 선택 유닛의 좌표, 이동 거리, 이동 회피, 방향별 엄폐 종류와 보너스 표시. 단순한 내장 IMGUI를 사용한다. |
| BattleSceneController | 초기화 순서를 조정하는 작은 연결 컴포넌트. 규칙 자체는 각 담당 클래스에 둔다. |
| BattleTestSceneBuilder | Editor 전용. 기본 Primitive, 재질, 컴포넌트 참조, 카메라와 테스트 Scene을 생성하는 메뉴 기능. 런타임 규칙은 포함하지 않는다. |

주요 튜닝 값은 SerializeField로 노출한다. 최소 크기, 양수 셀 크기,
이동 속도, 이동 범위를 검증한다. 코드와 수동 Scene 구성 방법을 함께 설명한다.

## 탐색과 이동 처리

동일 비용의 4방향 이동이므로 A*에 준하는 최단 경로 탐색으로 BFS를 사용한다.
범위 탐색에서 거리와 이전 셀을 기록하고, 목적지의 이전 셀을 역추적하여 경로를 만든다.
경로는 시작 셀을 제외하므로 경로 길이가 이동 칸 수와 같다.

1. 유닛 클릭으로 선택하고 도달 가능한 셀을 계산·표시한다.
2. 이동 가능한 셀을 클릭하면 최신 데이터로 경로를 다시 검증한다.
3. 이동 시작 시 이전 이동의 거리와 회피를 0으로 초기화하고 범위 표시를 숨긴다.
4. 일정한 Inspector 이동 속도로 각 셀 중심까지 움직인다. Capsule의 바닥 높이를 유지한다.
5. 다음 셀은 이동 전에 통행·점유를 확인한다. 셀 중심 도착 시 이전 셀을 비우고
   새 셀을 점유하며 현재 좌표와 이동 거리, 기동 회피를 갱신한다.
6. 이동 중에는 선택 변경과 추가 이동 명령을 막는다. 이번 스켈레톤은
   PlayerInputController를 통한 단일 유닛 이동만 허용하며 동시 이동은 지원하지 않는다.
7. 이동 완료 후 도착 셀의 엄폐와 새 이동 가능 범위를 표시한다.

이동 도중 경로가 막히면 마지막으로 점유한 셀 중심에서 중단한다.
실제로 도착한 칸 수만 회피에 반영한다. 범위 밖, 맵 밖, 막힌 셀 클릭은 무시한다.
이동 도중 엄폐 조회는 마지막으로 도착하여 점유한 셀을 기준으로 한다.

## 기동 회피

UnitMobility가 다음 규칙을 계산한다. 경로의 직선 거리나 월드 이동 거리는 사용하지 않는다.

| 이번 이동에서 도착한 칸 수 | MovementEvasion |
| --- | --- |
| 0 | 0 |
| 1~2 | 5 |
| 3~4 | 10 |
| 5 이상 | 15 |

구간별 보너스는 Inspector에서 조정 가능하게 한다. 새 이동마다 이전 값이 초기화된다.
기동 회피는 임시 보정값이며 기본 회피 능력치, 엄폐 보너스와 합치지 않는다.
향후 TurnManager는 명시적인 초기화 메서드를 호출할 수 있다.

## 엄폐와 장애물 배치·판정

엄폐는 셀을 차지하는 Cube 방식이다. CoverObject가 있는 Cube는 이동을 막는다.
Half/Full은 Inspector 설정으로 결정하며 Cube 높이에서 자동 추론하지 않는다.
높이는 사람이 종류를 구분할 수 있도록 Half와 Full을 다르게 표현한다.
Full은 해당 방향의 +30 보정이며 모든 방향 보호나 완전한 공격 차단을 의미하지 않는다.

기본 배치는 셀 중심에 맞춘 축 정렬 BoxCollider를 사용한다.
Collider의 월드 XZ footprint에 셀 중심이 들어가면 해당 셀을 차지한다.
작은 배치 오차가 인접 셀까지 막는 것을 피하기 위해 단순한 bounds 교차가 아닌
셀 중심 포함을 기준으로 한다. 큰 Cube는 여러 셀을 차지할 수 있다.
회전된 엄폐물과 셀 중심을 포함하지 않는 경계 벽은 이번 범위에서 지원하지 않는다.
등록할 셀이 없으면 해당 오브젝트 이름을 포함한 설명 가능한 경고를 남긴다.

CoverSystem은 각 엄폐 점유 셀의 상하좌우 인접 셀을 확인한다.
인접 셀에서 엄폐 셀을 바라보는 방향에 해당 종류를 등록한다.
예를 들어 (3,4)의 Full 엄폐는 (3,3) 셀에 North=Full을 제공한다.
엄폐가 겹치면 동일 방향에서 Full이 Half보다 우선한다.
일반 GridObstacle은 이동만 차단하며 엄폐를 제공하지 않는다.

엄폐·장애물은 Scene 시작 시 등록한다. 런타임 이동·파괴 자동 추적은 구현하지 않는다.
위치나 종류를 바꾼 효과는 Play를 다시 시작하여 확인한다.
유닛은 이동할 때 도착 셀의 엄폐 데이터를 조회하므로 방향별 상태가 자동으로 바뀐다.

## 초기화와 방어 처리

BattleSceneController는 그리드 생성 → 장애물·엄폐 등록 → 엄폐 계산 →
유닛 배치·점유 등록 → 입력·표시 연결 순서로 초기화한다.
Scene 참조를 Inspector에 명시적으로 연결하여 여러 컴포넌트의 Awake 순서에 의존하지 않는다.
유닛 시작 셀이 막히거나 다른 유닛과 겹치면 이름과 좌표를 포함한 경고를 내고
해당 유닛의 전투 참여를 비활성화한다. 자동으로 다른 셀에 옮기지 않는다.
필수 참조가 없으면 관련 기능을 중단하고 설명 가능한 진단을 남긴다.
정상 테스트 Scene에는 경고나 오류가 없어야 한다.

## 테스트 Scene과 표시

Assets/_Game/Scenes/BattleTest.unity를 별도로 만든다.

- 10×10, 셀 크기 2m 그리드와 Cube 바닥.
- Capsule 플레이어 유닛 1기. 기본 시작 좌표 (1,1), 이동 범위 5.
- Half Cover 2개: (3,2), (6,5).
- Full Cover 2개: (3,4), (7,7).
- 일반 장애물 3개: (4,2), (4,3), (4,4).
- 고정 Orthographic 쿼터뷰 카메라, Directional Light.
- Game View 그리드 선, 선택 표시, 이동 범위 셀 색상.
- Debug UI: 현재 좌표, Moved: N Cells, Movement Evasion: +N,
  North/East/South/West의 None/Half/Full과 개별 보너스.

점유 셀 차단 검증에서는 두 번째 Capsule을 임시로 복제하고 별도 시작 셀에 배치한다.
기본 Scene에 적이나 적 AI는 없다. 시각 표현은 모두 Unity 기본 기능으로 구성한다.

## 검증 계획

이미 설치된 Unity Test Framework를 사용하며 새 테스트 패키지는 추가하지 않는다.
규칙 검증은 Edit Mode 테스트, 조작과 화면 검증은 Play Mode 실행으로 확인한다.

- 좌표 변환: 첫 셀, 마지막 셀, 그리드 경계와 맵 밖.
- BFS: 4방향 최단 경로, 장애물 우회, 점유 셀 차단, 도달 불가,
  실제 경로 길이 5칸 제한과 시작 셀 제외.
- 이동 회피: 0, 1, 2, 3, 4, 5, 6칸의 구간값 및 새 이동 초기화.
- 엄폐: 네 방향, Half/Full 보너스, 다중 셀 Cube, 겹친 엄폐의 Full 우선,
  일반 장애물의 엄폐 없음.
- Play: 클릭 선택, 범위 표시, 부드러운 이동, 이동 중 재입력 차단,
  이동 후 점유·UI 갱신, 반복 이동, 방향별 엄폐와 기동 회피의 별도 표시.
- Console 오류·경고 없음. 실제 Unity 검증을 실행하지 못하면 그 한계를 명확히 보고한다.

## 향후 연결 지점과 제외 범위

공격 시스템은 BattleUnit의 MovementEvasion과 CoverSystem의 방향별 보너스를
각각 조회할 수 있다. 공격자 위치에서 방향을 고르거나 명중률을 합산하는 로직은 만들지 않는다.
TurnManager는 UnitMobility 초기화에 연결할 수 있으나 현재 턴 개념은 없다.

공격, 데미지, HP, 부위 파괴, 탄약, 무기, 파일럿 스탯·관계, 적 AI,
턴 순서, AP, 부스트, 열 관리, 기체 커스터마이징, Save/Load,
Mission System은 구현하지 않는다. 자유 배치 경계 벽, 동시 이동,
런타임 엄폐 파괴와 이동도 범위 밖이다.

## 구현 후 전달물

실행 가능한 테스트 Scene, 코드, 검증 결과와 함께 다음을 설명한다.
생성·수정 파일, 클래스 책임, 연결 흐름, 수동 Scene 구성 방법,
GameObject별 컴포넌트·참조 설정, 테스트 방법, 기동 회피 계산 위치,
엄폐 판정 방식, 향후 공격 시스템 연결 지점, 의도적으로 제외한 기능.

## 설계 검토

사용자는 셀 점유형 엄폐, 그리드 데이터 중심 관리, 책임 분리와 이동 흐름,
테스트 Scene 구성 및 검증 범위를 승인했다.
사용자는 작성된 설계 문서를 승인했고, 이 문서를 기준으로 구현 계획을 작성한다.
현재 폴더는 Git 저장소가 아니므로 문서를 파일로 저장하며 커밋하지 않는다.
