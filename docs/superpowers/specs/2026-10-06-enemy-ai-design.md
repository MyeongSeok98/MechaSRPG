# 기초 적 AI와 진영별 턴 설계

## 목적과 범위

현재 전투 스켈레톤에서 적도 자신의 AP로 이동·공격하도록 한다. 플레이어 턴 종료 후 적 기체를 한 기체씩 처리하고, 모두 끝나면 플레이어 턴으로 복귀한다. 플레이어의 이동·공격과 적 행동이 같은 그리드·점유·AP·명중률 규칙을 사용해야 한다.

사용자가 승인한 행동 범위는 즉시 공격, 공격 AP를 남긴 이동 후 공격, 공격이 어려울 때 접근, 길이 없을 때 대기다. 엄폐 자리 선택, 측면 공격, 집중 공격, 후퇴, 적 성격·무기·시야 시스템은 추가하지 않는다.

사용자가 직접 조정한 맵 크기, 장애물·엄폐물 배치, 기체 시작 위치, 카메라 구도와 Pan Speed 25는 보존한다. 실제 Scene을 예제 초기 배치로 재생성하지 않는다. 실제 배치 좌표와 카메라 속도를 고정값으로 검증하지 않는다.

## 진영별 턴

- 시작은 플레이어 턴이다. 플레이어는 여러 아군을 선택하여 각자의 AP로 행동한다.
- 턴 종료 요청은 플레이어 턴에서만 받는다. 이동 중이거나 전투 종료 후에는 거절한다.
- 종료 요청을 받으면 적 턴으로 전환한다. 플레이어 이동·공격·추가 턴 종료 요청은 차단한다. ESC와 카메라 조작은 계속 가능하다.
- 적은 BattleSceneController에 등록된 Units 순서로 한 기체씩 처리한다. 죽거나 비활성 상태인 적은 건너뛴다. 이동 완료를 기다린 다음 공격·다음 기체 행동으로 진행한다.
- 적 행동이 모두 끝나면 턴 번호를 증가시키고 다음 플레이어 턴을 시작한다. 번호는 플레이어·적 한 사이클을 기준으로 한다.
- 각 진영의 턴 시작에 그 진영의 살아 있는 기체 AP와 기동 회피를 초기화한다. 플레이어의 이동 회피는 적 턴 동안 유지되어 적 공격에 적용된다.
- 승리·패배가 확정되면 남은 적 행동과 다음 턴 전환을 중단한다. 종료된 전투에서 AP를 회복하지 않는다.
- 적 행동 사이에는 짧은 표시 간격을 둔다. 간격은 Inspector에서 조절하며, 불필요한 긴 대기나 별도 공격 애니메이션은 만들지 않는다.

## 기체별 AP와 공격

- AP는 기존 UnitActionPoints 인스턴스를 사용한다. 기본 최대 5, 실제 도착한 이동 칸마다 1, 공격당 3을 소모한다.
- AI는 자신의 UnitCombat.AttackCost, Range와 이동 범위를 읽는다. 5/3/2를 별도 AI 상수로 고정하지 않는다.
- 양쪽 진영 모두 반대 진영의 살아 있는 기체만 공격할 수 있다. 같은 진영 공격은 거절한다.
- 공격 미리보기와 실제 공격은 기존 CombatSystem을 사용한다. 사거리, 방향별 엄폐, 대상 기동 회피, 확률 판정, AP 소모, 피해·사망·점유 해제 규칙을 공유한다.
- 빗나가도 공격 AP를 소모한다. 불가능한 행동은 AP·HP·난수를 변경하지 않는다.
- 현재와 같이 사거리 내의 중간 장애물은 사격을 차단하지 않는다. 이번 변경에서 시야나 사격 경로 판정을 추가하지 않는다.

## 적 한 기체의 행동

1. **즉시 공격:** 현재 공격 가능한 플레이어 중 가까운 기체를 공격하고 해당 적의 행동을 마친다. 남은 AP로 추가 전술 이동은 하지 않는다.
2. **이동 후 공격:** 즉시 공격할 수 없다면 공격 사거리 안의 빈 셀까지 가는 경로를 찾는다. 자신의 AP에서 공격 비용을 뺀 이동 예산 안에 도달할 수 있으면 이동 후 다시 공격 조건을 확인하여 공격한다. 초기 수치에서는 최대 2칸 이동 후 AP 3으로 공격한다.
3. **접근:** 이번 턴 공격이 어렵다면 공격 가능한 위치까지의 경로를 따라 이동 범위·남은 AP 이내로 접근하고 행동을 마친다. 한 기체가 AP를 모두 사용하도록 강요하지 않는다.
4. **대기:** 공격도 접근도 할 수 없으면 아무 AP를 소모하지 않고 다음 적으로 넘어간다.

이동 후 공격 후보는 필요한 이동 칸 수가 적은 후보를 우선한다. 즉시 공격의 거리 동률과 그 밖의 동률은 등록된 플레이어 기체 순서 및 기존 BFS 탐색 순서를 사용하여 재현 가능하게 만든다. 도달 불가능한 대상만 붙잡고 멈추지 않고 다른 살아 있는 대상을 확인한다.

유효하지 않은 상태, 이동 중 중단, 대상 제거가 발생하면 현재 상태를 다시 확인한다. 불가능해진 공격을 강행하거나 같은 실패 명령을 무한 반복하지 않는다.

## 경로와 점유

그리드 이동 비용이 모두 1인 현재 규칙에 맞춰 BFS를 사용한다. 이동 가능한 셀과 다른 기체 점유를 기존 규칙으로 판정한다. 적도 다른 적·아군·장애물이 있는 셀을 통과하지 않는다.

플레이어가 점유한 셀까지 직접 경로를 찾는 대신, 그 플레이어를 공격할 수 있는 빈 셀을 목적지로 사용한다. 접근 경로 탐색은 한 턴 이동 범위보다 멀리까지 길을 찾을 수 있도록 하되, 실제 이동 명령은 이번 턴 이동 가능 거리까지만 내린다. 이렇게 하여 장애물을 우회하는 도중 잠시 대상과 멀어지는 길도 따라갈 수 있다.

전체 경로 탐색과 실제 이동 실행을 구분한다. 실제 이동은 기존 UnitMovement를 사용하고, 도착 시점의 점유·생존·AP 검사를 그대로 유지한다. 여러 적의 이동을 동시에 시작하지 않는다.

## 책임 분리와 연결

- **TurnManager:** 현재 진영, 턴 시작·종료, 진영별 AP·회피 초기화, 행동 권한, 적 행동 순서 실행 및 전투 종료 관리.
- **EnemyAIController:** 적 한 기체의 목표·경로·행동 선택과 이동 완료 대기, 공통 CombatSystem 호출. 별도 피해·AP 계산을 만들지 않는다.
- **Pathfinder:** 기존 플레이어 이동 탐색 유지, 적 접근을 위한 더 먼 목적지 경로 탐색 지원. 턴 변경이나 공격 실행은 하지 않는다.
- **CombatSystem:** 반대 진영 공격과 현재 턴의 행동 권한을 검사하고 양쪽에 같은 전투 규칙 적용.
- **PlayerInputController / BattleDebugUI:** 적 턴에는 플레이어 전투 행동을 거절하고 이동 범위·버튼 상태를 현재 턴에 맞춰 갱신한다. 현재 진영과 적 행동 중임을 표시한다. 기체 선택, ESC 취소, 카메라 조작은 전투 행동과 분리하되 이동 중 선택 제한은 기존 정책을 따른다.
- **BattleSceneController / Scene Builder:** 기존 Units와 공통 시스템을 연결한다. 기존 Scene은 필요한 AI 컴포넌트·연결만 보완하고 작성된 배치·설정·참조를 보존한다. 새로 생성하는 예제 Scene도 같은 구성을 사용한다.

필요한 기초 컴포넌트만 추가한다. 행동 트리, 범용 AI 프레임워크, 상태별 전략 클래스 같은 확장용 추상화는 만들지 않는다.

## 검증 범위

자동 테스트는 직접 구성한 임시 그리드·기체·장애물을 사용한다. 기존 저장 Scene의 고정 좌표·장애물 이름·카메라 속도에 의존하는 배치 테스트는 해당 임시 구성으로 이동하거나 사용자 작성 값에 의존하지 않는 초기화 검증으로 제한한다.

- 플레이어 → 적 → 플레이어 전환, 적 턴 중 플레이어 이동·공격·중복 종료 거절.
- 여러 아군·적의 독립 AP, 해당 진영만 턴 시작 초기화, 플레이어 회피가 적 공격까지 유지됨.
- 적 즉시 공격의 성공·실패 확률, 피해·엄폐·회피·AP 공통 계산, 같은 진영 공격 거절.
- 최대 2칸 이동 후 공격, 더 먼 대상 접근, 장애물 우회, 다른 기체 점유 회피, 길이 없는 경우 대기.
- 여러 적이 한 기체씩 행동하고, 앞 기체 행동으로 변한 점유·생존 상태를 다음 기체가 반영함.
- 플레이어 처치 시 패배, 마지막 적 처치 시 승리, 남은 AI 행동과 다음 턴 시작 중단.
- 적 제거·비활성·이동 중단 시 무한 대기나 중복 행동 방지, AI/턴 컴포넌트 비활성 시 실행 중단.
- 기존 선택·ESC·WASD·Q/E·더블클릭 중앙 배치 및 AP·이동·공격 회귀 검증.
- 실제 Scene 갱신 전후 작성 데이터 보존 비교. 사용자 장애물 좌표나 Pan Speed 25를 예제 값으로 맞추지 않음.

난수와 행동 표시 간격은 테스트에서 제어하여 결과를 재현 가능하게 한다. 실제 OS 마우스 사용감이나 추가 공격 애니메이션은 자동 검증 범위에 포함하지 않는다.
