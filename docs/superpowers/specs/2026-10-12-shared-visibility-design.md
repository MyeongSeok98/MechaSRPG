# 소대 공유 시야·탐지 설계

상태: 2026-10-12 사용자 승인으로 설계 확정. 구현은 별도 계획 검토 후 진행한다.

추가 승인: 2026-10-13 전장의 안개 3단계 표시와 지형 탐험 기록을 포함한다. 장애물·골짜기·엄폐물은 미탐험 영역에서도 형태를 볼 수 있게 유지한다.

## 목적과 범위

소대가 실제로 볼 수 있는 적만 표시·조준하고, 적 AI도 발견한 아군에게만 접근·공격한다. 전투 시작부터 탐지를 적용하고, 진영 전체가 시야를 잃으면 추적 기억 없이 목표를 버린다.

사용자와 합의한 사항: 진영별 시야 공유, 미발견 적 AI 대기, 시야 상실 후 다시 대기, 시작 시 즉시 발견. 앞서 제안한 기본 탐지 거리 10칸·360도 원형을 초기값으로 사용한다. 방향별 시야 제한은 없다.

이번 범위는 유닛 탐지, 표시·조준·AI 연동과 지형의 전장의 안개다. 지형은 계속 보이며 탐험 기록에 따라 밝기를 구분한다. 적의 마지막 목격 위치, 순찰, 은신 확률, 숲, 소리, 센서·머리 손상에 따른 탐지 변화는 구현하지 않는다.

## 탐지 규칙

- 관측자는 초기화되고 활성화되어 그리드에 등록된 Active 기체다. AP나 현재 행동 진영에 관계없이 관측한다.
- Critical 기체는 관측 능력을 잃지만 탐지 대상에는 남는다. 파괴·탈출·제거된 기체는 관측자와 대상에서 제외한다.
- 거리 단위는 Cell이다. 두 칸 좌표 차이의 제곱합이 탐지 거리의 제곱 이하이면 거리 조건을 만족한다. 예를 들어 거리 10에서 (6,8)은 포함하고 (8,8)은 제외한다.
- 자기 진영은 항상 표시한다. 상대 진영은 유효한 관측자 한 기라도 거리와 직선 시야 조건을 만족하면 발견한다.
- 발견은 확률 판정이 아니다. 매 갱신의 현재 위치와 차폐 상태로 결정한다.
- 건물은 시야를 막는다. Half/Full 엄폐, 골짜기와 다른 유닛은 시야를 막지 않는다. 기존 엄폐 명중률 규칙은 유지한다.
- 시야 직선의 건물 모서리 판정은 기존 HasClearShot의 보수적인 그리드 통과 규칙과 일치한다. 대각선 모서리에 닿은 양옆 칸 중 하나가 건물이면 차단한다.
- 시야는 높이를 고려하지 않는 현재의 2D 그리드 판정이다. 3D 렌더링과 판정을 분리한다.

## 공유 및 공격

플레이어와 적은 각각 진영 전체의 탐지 결과를 공유한다. A가 발견한 적을 B도 확인할 수 있지만, B의 공격은 기존 사거리·자기 위치에서의 사격 차단·AP·상태 검사를 통과해야 한다. 공유 탐지가 건물을 관통하는 공격을 허용하지 않는다.

근접과 원거리 모두 발견된 상대만 선택·공격한다. CombatSystem에서도 탐지를 검사하여 직접 TryAttack 호출로 제한을 우회하지 못하게 한다. 기존 피해·명중률·부위 조준·사거리 계산은 변경하지 않는다.

진영 전체가 대상의 시야를 잃으면 즉시 탐지 결과에서 제거한다. 플레이어의 해당 목표 선택, 명중률 미리보기와 부위 조준 창도 해제한다. 새로 나타난 적을 자동 조준하지는 않는다.

## 적 AI

- 행동 시작 시 적 진영에 발견된 플레이어 기체만 후보에 넣는다.
- 후보가 없으면 이동·공격·AP 소비 없이 해당 기체의 행동을 마친다. 적 턴 전체는 정상적으로 다음 기체와 플레이어 턴으로 진행한다.
- 발견된 대상이 있으면 기존 근접/원거리 선택과 접근·공격 규칙을 유지한다.
- 이동 중에도 매 완료 칸에서 공유 탐지가 갱신된다. 목표가 진영 시야에서 사라지면 현재 이동을 취소하여 마지막 완료 칸에 정착하고 그 행동을 종료한다. 완료 칸의 AP만 소비한다.
- 다음 적 기체는 최신 탐지 결과로 다시 판단한다. 마지막 목격 좌표, 숨겨진 현재 위치, 추적 목적지는 저장하지 않는다.
- 발견이 플레이어 턴에 발생하더라도 적이 즉시 끼어들어 공격하지 않는다. 기존 진영별 턴을 유지한다.

## 갱신 시점과 책임

`UnitVision`은 Inspector에서 조절할 탐지 거리(기본 10칸)를 가진다. 기존 유닛에 이 컴포넌트가 없으면 전투 초기화 시 기본값으로 보완하여 세 전투 씬 모두 작동하게 한다. 편집 시 유닛/프리팹에 UnitVision을 추가하면 개별 탐지 거리를 설정할 수 있다.

`VisibilitySystem`은 그리드와 전투 등록 유닛을 받아 진영별 탐지 결과를 계산하고 변경을 알린다. BattleSceneController가 기존 시스템과 함께 초기화한다. 중복 초기화·중복 구독을 방지한다.

갱신은 다음 시점에 수행한다.

1. 전투 시작: 장애물·엄폐·유닛 배치와 상태 초기화가 끝난 후, 초기 탐지 결과를 표시·입력·AI에 연결한다. 게임 첫 화면부터 범위 내 가려지지 않은 적을 표시한다.
2. 이동: 그리드 점유와 CurrentGridPosition이 완료 칸으로 변경된 후. 보간 중간 좌표는 사용하지 않는다.
3. 관측자/대상의 상태 변경·비활성화·제거 및 턴 시작: 유효한 등록 유닛만 다시 평가한다.

GridCell의 시야 차단 상태는 총알 차단 상태와 별도로 관리한다. 초기 장애물 등록에서는 기존 BlocksShots 건물 설정을 시야 차단 초기값으로 사용한다. 따라서 기존 골짜기의 BlocksShots=false는 시야도 막지 않으며, 씬의 장애물 위치나 기존 설정을 바꿀 필요가 없다. 그리드 직선 통과 계산은 작은 공통 함수로 재사용하고 사격·시야의 차단 조건만 분리한다. 연막 같은 새로운 차폐물은 이번 범위 밖이다.

## 표시와 생명주기

숨겨진 적의 GameObject나 BattleUnit을 비활성화하지 않는다. 그리드 점유, 상태, 턴 참여와 승패 판정은 유지한다. 탐지 표시 전용 처리가 모델 렌더러만 숨기고, 기존 비활성 렌더러를 무조건 다시 켜지 않는다. 그림자를 통한 위치 노출도 막는다.

숨겨진 적은 클릭·목표 선택·부위 조준으로 선택할 수 없으며, 적 행동의 빨간 바닥 표시도 플레이어에게 발견된 적에게만 나온다. 입력 제한은 Collider 활성화 상태에 의존하지 않고 탐지 결과를 검사한다. 플레이어 유닛과 지형 표시는 유지한다.

파괴·탈출로 숨겨진 모델을 탐지 표시 갱신이 다시 켜지 않게 한다. 구독은 비활성화·파괴 때 정리한다. 전투 종료 이후 새 AI 행동을 발생시키지 않는다. 비활성화된 탐지 시스템 때문에 미발견 대상에게 공격이 허용되는 방식으로 실패하지 않는다.

이번 단계에서는 실제 점유 정보를 사용하는 기존 이동 경로 계산을 유지한다. 숨겨진 유닛 칸은 여전히 통과할 수 없으므로 이동 범위 모양으로 점유를 간접 추측할 수 있는 한계는 남는다. 이를 없애는 별도의 미지 점유·충돌 후 발견 시스템은 포함하지 않는다. 발견하지 못한 적의 위치·상태를 전용 UI로 표시하지 않는다.

## 전장의 안개와 지형 탐험 기록

지형 상태는 각 진영의 공유 시야를 기준으로 칸별 관리한다. 화면에는 플레이어 진영의 상태를 사용한다.

| 상태 | 지형 표시 | 적 표시 |
|---|---|---|
| 현재 시야 안(Visible) | 원래 색상과 밝기 | 탐지된 적 표시 |
| 탐험했지만 현재 시야 밖(Explored) | 회색으로 어둡게 | 숨김 |
| 아직 미탐험(Unexplored) | 더 짙은 회색, 형태는 식별 가능 | 숨김 |

- 지면·건물/장애물·골짜기·Half/Full 엄폐물은 세 상태에서 모두 표시한다. 미탐험 지형을 검정이나 불투명 덮개로 완전히 가리지 않는다.
- 아군과 조작 UI·선택/이동/공격 표시에는 회색 효과를 적용하지 않는다. 숨겨진 적은 회색 실루엣이나 그림자로 표시하지 않는다.
- 지형 기록과 적의 추적 기억은 별개다. 과거 탐험한 칸이어도 현재 볼 수 없는 적의 위치·상태는 표시하거나 AI가 기억하지 않는다.
- 전투 시작 시 전체 지형을 Unexplored로 초기화한 뒤 아군 초기 시야의 칸을 Visible로 만든다. 한 번 Visible이 된 칸은 시야를 잃으면 Explored가 되며 다시 Unexplored로 돌아가지 않는다. 새 전투에서는 기록을 초기화한다. 전투 간 저장 기능은 포함하지 않는다.
- 시야 칸은 같은 10칸 원형 거리·건물 차폐 규칙과 갱신 시점을 사용한다. 관측자에서 건물 칸까지 가는 중간 경로가 열려 있다면 최초 차폐 건물 칸 자체는 Visible로 보이고, 그 뒤의 칸은 가려진다. 유닛 탐지의 기존 차폐 규칙은 유지한다.
- 건물·큰 지면처럼 여러 칸을 차지하는 렌더러는 오브젝트 전체를 중심 칸 하나로 판정하지 않고 표면의 월드 X/Z 위치로 상태를 적용한다. 안개 경계가 건물 옆면과 지면에 함께 반영되어야 한다.
- 두 회색 상태의 밝기는 Inspector에서 조절 가능하게 한다. 현재 시야는 원래 모습을 유지하며, 두 회색 상태는 색뿐 아니라 명암으로도 구분한다.
- 표시 구현은 지형 전용이며 원본 머티리얼·텍스처·씬·모델을 덮어쓰지 않는다. 카메라 방향·줌·그림자 표시 거리와 탐지 판정은 서로 독립이다.

## 검증 범위

- 시작 시 거리 내 적 즉시 발견, 거리 밖과 건물 뒤 적 미발견.
- 원형 거리 경계·대각선 및 건물 모서리 차폐.
- Half/Full 엄폐와 골짜기가 탐지를 막지 않음.
- A가 발견한 적을 B도 조준하되 B 자신의 사거리와 건물 차단은 유지.
- 관측자 한 기의 시야만 잃으면 공유 유지, 마지막 관측자의 시야 상실 시 숨김·조준 해제.
- 이동 완료 칸마다 발견/상실 반영, 이동 중 목표 상실 시 적의 추적 취소·완료 칸 AP 유지.
- 미발견 AI 대기·AP 보존·턴 진행, 시작부터 발견된 AI의 기존 행동 유지.
- 숨긴 적의 점유·상태·승패 로직 유지, 렌더러/그림자/빨간 표시/선택에서 위치 노출 방지.
- Critical·파괴·탈출·비활성화 후 관측 갱신과 표시 정리, 중복 초기화 방지.
- 지형의 Unexplored → Visible → Explored → Visible 전환과 새 전투의 기록 초기화.
- 첫 차폐 건물은 보이고 그 뒤는 가려짐. 이동 중 공유 시야와 칸 탐험 기록 일치.
- 미탐험에서도 장애물·골짜기·엄폐물이 식별되고, 큰 건물/지면은 표면 위치에 맞게 세 상태 표시.
- 아군·UI의 원래 색상 유지와 숨겨진 적의 실루엣/그림자 노출 방지. 지형 탐험 기록이 적의 추적 기억을 만들지 않음.
- 분리 검증 프로젝트에서 화면을 렌더링하여 세 상태를 시각 확인하고 원본 머티리얼 복원을 검증.
- 기존 이동·방향 확정·공격·엄폐·카메라 테스트와 전체 EditMode/PlayMode 회귀. 테스트용 전투 fixture는 탐지를 명시적으로 초기화하여 새 규칙을 검증한다.

## 보존 사항

사용자가 변경한 zoomSpeed=60f, Shadow Max Distance, 이동속도 12f, 카메라 이동속도, 맵 크기·배치, 라이플 손잡이·위치·모델 설정은 수정하거나 기본값으로 되돌리지 않는다. 저장된 전투 씬은 구성 보완 때문에 재저장하지 않고 공통 초기화로 연결한다.

설계 승인 후 별도 구현계획을 작성한다. 이번 문서 작성 단계에서는 런타임 코드와 사용자 자산을 변경하지 않는다.
