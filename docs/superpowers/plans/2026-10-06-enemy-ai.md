# 기초 적 AI와 진영별 턴 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 플레이어 턴 종료 후 적이 개별 AP로 순차 이동·공격하고, 완료 후 다음 플레이어 턴으로 복귀하도록 한다.

**Architecture:** TurnManager가 진영·권한·순서·턴 복귀를 관리하고 EnemyAIController가 적 한 기체의 행동을 실행한다. 공통 CombatSystem과 UnitMovement를 재사용하고, Pathfinder에 공격 사거리까지의 전체 경로 탐색을 추가한다. 기존 씬은 런타임 연결로 호환시키며, 배치 의존 검증은 테스트 전용 씬에서 수행한다.

**Tech Stack:** Unity 6000.5.5f1, C#, Input System, Unity Test Framework, NUnit, 기존 URP 프로젝트. 외부 패키지 추가 없음.

**Spec:** [승인된 설계](../specs/2026-10-06-enemy-ai-design.md)

## Global Constraints

- 기본 기체별 AP 5, 도착한 이동 칸당 1, 공격당 3. AI는 UnitCombat.AttackCost·Range와 기체 이동 범위를 읽는다.
- 플레이어 이동 회피는 적 턴 동안 유지하고, 각 진영의 턴 시작에 해당 진영만 AP·회피 초기화한다.
- 적은 등록된 Units 순서로 한 기체씩 실행한다. 플레이어·적 한 사이클마다 TurnNumber가 증가한다.
- 같은 진영 공격 금지. 양쪽이 같은 사거리·확률·엄폐·회피·피해 규칙을 사용한다. 사격 경로·시야 판정은 추가하지 않는다.
- 사용자가 직접 조정한 맵 크기, 장애물·엄폐물 배치, 기체 시작 위치, 카메라 구도와 Pan Speed 25는 보존한다.
- 실제 BattleTest.unity를 재생성·저장하거나 예제 좌표로 맞추지 않는다. 실제 장애물 좌표·카메라 속도의 고정값 검증도 하지 않는다.
- 새 코드·테스트는 Assets/_Game 안에 두고 namespace MechaXCOM / MechaXCOM.Tests를 사용한다.
- 엄폐 탐색·측면 공격·집중 공격·후퇴·행동 트리·자동 카메라 추적은 제외한다.
- Unity Editor가 원본 프로젝트를 열고 있으면 동시 배치 실행을 하지 않는다. 필요 시 테스트용 사본을 사용하며, 그 결과와 원본 코드의 동일성을 기록한다.
- 실행 시 Git 상태부터 확인한다. 현재처럼 Git 저장소가 없으면 임의로 초기화·브랜치·worktree를 만들지 않고 Artifacts에 검증 기록을 남긴다. 저장소가 있다면 승인된 실행 방식과 worktree 스킬에 맞춰 격리하고 작업 단위로 커밋한다.

## Review Focus

1. **실행 중 AI/턴 컴포넌트 비활성화:** 진행 중 적 이동을 안전하게 취소하고 재활성화 시 이미 처리한 적을 반복하지 않음. Task 1·2 테스트.
2. **가장 가까운 플레이어에 경로가 없음:** 다른 도달 가능한 대상을 사용하고, 우회 과정에서 거리 증가를 허용함. Task 1·2 테스트.
3. **이동 중 대상 제거·비활성·AP 컴포넌트 중단:** 오래된 결정을 강행하거나 AP를 중복 소모하지 않고 다음 적으로 진행함. Task 2 테스트.
4. **선택한 기체가 있는 상태에서 진영 변경:** 적 턴에 범위·행동 버튼을 갱신하고, ESC·카메라 기능과 기체별 AP 보존. Task 3 테스트.
5. **기존 씬의 사용자 참조·비활성 기체·명시적 빈 목록:** 연결 시 배치나 기존 참조를 고치지 않고 AI를 중복 생성하지 않음. Task 4의 임시 씬 테스트.

## 실행 방식 및 완료 기준

권장 방식은 **Native**다. 네 작업이 경로·턴·전투 인터페이스로 이어지므로 같은 세션에서 직접 순차 구현하고 끝에 독립 검토를 한 번 받는 방식이 적합하다. 사용자가 Subagent-driven을 선택하면 해당 스킬의 작업별 검토 절차를 따른다.

완료 기준은 승인 설계의 행동 네 종류·진영별 턴·공통 전투·독립 AP가 실제 임시 전투에서 동작하고, 전체 테스트 실패가 0이며, 원본 씬과 사용자 작성 설정이 변경되지 않는 것이다. 단계별 구현·검증과 다음 작업의 확인 대기 상태는 `Artifacts/enemy-ai-progress.md`에 기록한다.
