# 기체별 AP당 이동거리와 턴 누적 이동 비용

MechaData Inspector의 **AP당 이동거리 (칸/AP)**에서 기체마다 값을 직접 입력한다. 기본1이며0보다 큰 유한한 수를 사용한다. 예를 들어1, 1.5, 2를 입력할 수 있다. 초기 밸런싱은0.5칸 간격으로 해볼 수 있지만 코드가 그 간격으로 제한하지는 않는다.

## B 방식: 이미 지불한 이동분 유지

효율이 일정할 때 비용은 다음과 같다.

```text
누적 이동 AP = 올림(자기 턴 누적 이동 칸 / AP당 이동거리)
이번 차감 AP = 새 누적 이동 AP - 이미 지불한 이동 AP
```

이동 중 각 칸에 도착할 때 차감한다. 턴 종료 때 한꺼번에 청구하지 않는다. 이동·사격·이동을 나눠도 이미 지불한 이동 여유분은 유지한다. 사격·재장전·경계·탈출 AP는 별도 자원 소모로서 이 이동 여유를 소비하지 않는다.

예: AP5, AP당2칸, 사격3AP.

| 행동 | 이번 AP | 남은 AP | 선불 이동 여유 |
|---|---:|---:|---|
| 1칸 이동 | 1 | 4 | 1칸 |
| 사격 | 3 | 1 | 1칸 |
| 1칸 이동 | 0 | 1 | 없음 |
| 2칸 이동 | 1 | 0 | 없음 |

AP0이어도 이미 지불한 여유로 한 칸 이상을 완주할 수 있으면 Move를 사용할 수 있다. 예를 들어 AP당3칸인 기체가1칸 이동에1AP를 냈다면 남은2칸은 이미 지불한 이동이다. 이 여유는 AP로 환급하거나 다른 행동 비용으로 사용할 수 없다.

자기 턴 동안에만 사용할 수 있고 다음 자기 턴 시작에 AP와 장부를 초기화한다. 선택 해제·무기 변경·이동 명령 취소·컴포넌트 재활성화·같은 BattleUnit 재초기화로 초기화하지 않는다. 자기 턴 시작 때 비활성화된 생존 기체도 새 턴 장부로 갱신한다.

## 손상과 중단

- 다리 둘 다 정상: 기체 기본 이동 효율.
- 다리 하나 파괴: AP당 이동거리×0.5. 예:2칸/AP→1칸/AP.
- 다리 둘 다 파괴: 선불 여유가 있어도 이동 불가.

다리가 파괴되기 전의 이동은 다시 청구하지 않는다. 다음 칸부터 낮아진 효율로 계산한다. 선불 여유는 AP의 일부로 기록하므로 효율이 바뀌면 그 여유로 갈 수 있는 칸 수 역시 달라진다. 실제 이동 중에는 매 칸 비용·손상·점유·경계사격 결과를 재검사하고 더 이동할 수 없으면 마지막 도착 칸에서 멈춘다.

부분 애니메이션에서 취소하거나 장애물 때문에 중단되면 도착한 칸까지만 지불한다. 예측했던 최종 목적지까지 미리 전액 차감하지 않는다. 이동 도중 그리드가 교체되어 기존 경로가 유효하지 않으면 해당 미도착 칸을 청구하지 않는다.

## 범위·AI·기존 설정

기체 데이터가 있는 유닛은 기존 BattleUnit의 고정 Movement Range 대신 AP와 선불 여유로 이동 범위를 계산한다. 예를 들어 AP5·효율2면 열린 맵에서 최대10칸이며 기존5칸 상한에 막히지 않는다. 경로의 실제 이동 칸 수가 기준이며 장애물은 우회해야 한다. 현재는 균일 지형 비용이므로 BFS를 유지한다.

기체 데이터가 없는 이전 유닛은 효율1과 기존 명령별 이동 범위·다리 범위 제한을 유지한다. 실제 이동 속도12f는 애니메이션 속도이며 비용이나 이동 효율과 별개다. 이동 거리 회피/진단용 UnitMobility는 이전처럼 이동 명령별로 기록하고, 새 AP 장부는 별도로 유지한다.

플레이어 범위·Move 가용성·실제 이동·AI는 같은 비용을 사용한다. AI는 이동 칸 수를 AP로 간주하지 않고 실제 예상 이동 AP를 계산해 공격 비용을 남긴다. 기존 한 번의 이동/공격 판단 정책을 확장해 별도 이동-사격-이동 전술을 추가한 것은 아니다.

## 추가부품 확장

```text
MechaData.MovementCellsPerAP
  ↓ 첫 전투 초기화에 복사
BattleUnit.BaseMovementCellsPerAP
  ↓ GetMovementCellsPerAP() : 미래 부품 보정 연결 지점 + 다리 손상
UnitMovement / MovementCostLedger
  ↓
범위·예상 AP·실제 이동·AI
```

기체 기본값과 최종 효율을 분리했다. 추후 부품은 공유 MechaData를 수정하지 않고 기체별 최종 효율 함수에 연결한다. 부품 수치·합산 규칙·장착 시스템은 아직 구현하지 않는다. Play 중 기체 데이터를 바꿔도 기존 기체 기본값은 갱신하지 않으므로 전투를 다시 시작해 확인한다.

코드는 Assets/_Game/Scripts의 Unit/MovementCostLedger.cs, Unit/UnitMovement.cs, Unit/BattleUnit.cs, Turn/TurnManager.cs, AI/EnemyAIController.cs에 있다.
