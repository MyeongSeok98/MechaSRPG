# 통신소·고정포대 데이터

통신소 데이터는 CoverDurability를 통해 단일 HP와 모든 무기 피격에 연결했고 [통신소 파괴 샘플 씬](destroy-station-mission.ko.md)을 제공합니다. 시설은 기본 무기 피해를 받고 일반 엄폐물의 폭발 전용 규칙과 구분합니다. 고정포대는 현재 정의 데이터까지이며 포대의 AP/잔탄/AI 연결은 아직 없습니다.

## 샘플 편집

Project 창에서 다음 에셋을 선택합니다.

| 에셋 | 종류 | 초기 설정 |
|---|---|---|
| `Assets/_Game/Data/Objects/SampleCommunicationStation.asset` | DestructibleObjectData | 통신소, 최대 HP2000 |
| `Assets/_Game/Data/Objects/SampleFixedTurret.asset` | TurretData | 최대 HP2500, 기본 AP5, 탐지10칸, 기존 StandardRifle |

두 샘플의 모델 프리팹은 미지정이며 나중에 Inspector에서 연결할 수 있습니다. HP·AP·탐지 값은 샘플 조절값입니다.

새 데이터는 `Create → MechaXCOM → Destructible Object Data` 또는 `Turret Data`로 만듭니다. `Assets/_Game/Data/Objects/`에 저장하는 것을 권장합니다.

## 데이터 구조

`DestructibleObjectData`는 오브젝트 ID·이름·설명·단일 최대 HP·선택 모델 프리팹을 정의합니다. 통신소뿐 아니라 발전기·연료탱크 등 공격하지 않는 시설에도 사용할 수 있습니다.

`TurretData`는 위 공통 설정을 상속하고 기본 AP·탐지 거리·고정 원거리 무장을 추가합니다. 이름과 HP를 다른 에셋에 중복 지정하지 않습니다. MechaData를 상속하지 않으므로 팔·다리·콕피트·파일럿 정보는 없습니다. 이동 데이터도 두지 않습니다.

피해·명중률·사거리·발사 AP·장탄 설정은 연결된 기존 `WeaponData`를 참조합니다. 샘플 포대는 `StandardRifle.asset`을 공유합니다. 무장에 따라 다른 포대 데이터를 만들려면 포대 에셋을 복제하고 ID·무장 등을 바꾸면 됩니다.

ID와 최대 HP는 필수이며 HP는1 이상이어야 합니다. 포대는 AP1 이상·탐지0 이상, 유효한 원거리 무장을 요구합니다. 무장의 발사 AP가 포대 기본 AP보다 크면 오류 안내를 표시합니다. 모델은 없어도 유효합니다. 이름을 비우면 에셋 이름을 표시합니다.

## 정의와 인스턴스 구분

데이터 ID는 시설/포대 종류를 구분합니다. 같은 통신소 데이터를 여러 번 배치할 수 있으며, 임무에서 어느 한 통신소만 지정하는 씬 인스턴스 ID와는 별개입니다. 해당 연결은 후속 MissionTarget 기능에서 처리할 수 있습니다.

현재 HP·남은 AP·잔탄·진영·배치 위치는 각 오브젝트 인스턴스에 속할 상태입니다. 공유 에셋에 전투 진행 상태를 저장하지 않습니다. 시설은 CoverDurability의 오브젝트 데이터에 연결합니다. 데이터 미지정 시 기존 프리팹 HP를 사용하므로 HP를 두 벌로 관리하지 않습니다. 고정포대의 전투 동작은 후속 연결이 필요하며 기존 BattleUnit에 이 에셋을 직접 대입할 수는 없습니다.

## 검증

2026-11-09 전체 EditMode **1002/1002** 통과. 상속한 공통 필드와 원거리 무장 참조의 에셋 저장·재로딩, 필수 ID/HP/AP/탐지·무장 유효성, 샘플2개의 참조를 검증했습니다. 런타임 코드나 기존 씬을 변경하지 않은 데이터 작업으로 PlayMode는 재실행하지 않았습니다.
