# MechaXCOM

메카 용병단을 지휘하며 지형·엄폐·무장·기체 손상을 관리하는 **Unity 기반 3D 턴제 전술 게임** 프로젝트입니다.

`기동전사 건담 제08MS소대`처럼 흙먼지 나는 육상전을 지향합니다. 메카를 거대한 보병 또는 장갑전투차량처럼 다루며, 건물과 폐허를 이용한 엄폐, 소대 단위의 우회와 집중 사격, 위험한 기체의 탈출 판단을 전투의 중심에 둡니다.

현재는 **전투 시스템을 검증하는 프로토타입**입니다. 용병단 운영과 캠페인보다 이동·공격·부위 손상·시야·경계사격의 기초를 먼저 구현하고 있습니다.

## 게임의 방향

플레이어는 한 명의 파일럿이 아닌 용병단의 지휘관입니다. 장기적으로는 3~5기의 소대를 구성하고, 파일럿과 기체·무장을 배정해 임무에 투입하는 흐름을 목표로 합니다.

```text
용병단 기지 → 의뢰 선택 → 파일럿·기체·무장 편성 → 출격
→ 턴제 전투 → 승리 / 실패 / 철수 → 수리·보충·파일럿 관리
```

목표는 적을 격파하는 것과 함께 파일럿과 기체를 살아서 돌아오게 만드는 것입니다. 전투 중 유한 탄약과 재장전을 구현했으며, 임무 후 탄약 보충·정비, 파일럿 생존과 영구 사망, 관계 변화 등은 향후 개발 대상입니다.

## 실행 방법

1. Unity Hub에서 프로젝트 루트 폴더를 엽니다.
2. 프로젝트 기준 에디터 버전인 **Unity 6000.5.5f1**을 사용합니다. 렌더 파이프라인은 URP입니다.
3. 다음 샘플 씬 중 하나를 열고 Play를 누릅니다.

| 씬 | 용도 |
|---|---|
| [SqurdWeaponTest](Assets/_Game/Scenes/SqurdWeaponTest.unity) | 아군·적 각각 3기의 소대전과 장착 무기 검증 |
| [1V1Test](Assets/_Game/Scenes/1V1Test.unity) | 소규모 전투 규칙 검증 |
| [EliminationMissionTest](Assets/_Game/Scenes/EliminationMissionTest.unity) | MissionData와 지정 적 3기의 Destroyed 섬멸 목표 검증 |
| [DestroyCommunicationStationTest](Assets/_Game/Scenes/DestroyCommunicationStationTest.unity) | 아군2·적2, 모든 무기로 통신소 공격 가능·파괴 시 성공 |

`SqurdWeaponTest`는 현재 파일 이름 그대로 표기했습니다. 샘플 수치와 배치는 씬 및 데이터 에셋 설정에 따라 달라질 수 있습니다.

## 현재 구현된 기능

### 그리드 이동과 진영 턴

- 3D 맵에서 Grid 기반 이동·점유·경로 탐색을 처리합니다.
- 상하좌우로 이동하며 이동 범위와 남은 AP에 맞는 칸을 표시합니다.
- 유닛·장애물이 점유한 칸과 골짜기 등 이동 불가 칸을 통과할 수 없습니다.
- 이동 경로 한 칸마다 AP 1을 소비하며 모델이 진행 방향을 바라봅니다.
- 이동 후 북·동·남·서 중 최종 방향을 선택할 수 있습니다.
- 플레이어 진영과 적 진영이 번갈아 행동합니다. 각 기체는 독립적인 AP를 가지며 자기 진영 턴 시작 시 최대치로 회복합니다.
- 진영 턴 시작에는 YOUR TURN / ENEMY TURN 배너가 오른쪽에서 들어와 중앙에 0.4초 머물고 왼쪽으로 사라집니다. 표시 중에는 플레이어 조작·카메라와 적 AI 시작을 기다립니다.
- 기본 AP는 5이며 기체 데이터로 변경할 수 있습니다.
- MissionController가 공통 아군 전멸 실패와 임무별 성공·실패 요청을 판단하고 TurnManager가 전투를 중단합니다. 기존 씬의 적 전멸 승리는 호환 설정으로 유지하며 새 임무에는 강제하지 않습니다.

### 엄폐와 사선

- Half / Full Cover를 방향별로 관리합니다.
- 상하좌우 공격은 해당 방향 엄폐를 사용합니다. 대각선 공격은 해당 대각선과 양옆 방향 중 가장 강한 엄폐 하나를 사용합니다.
- 기본 명중 배율은 Half Cover ×0.75, Full Cover ×0.5입니다.
- 건물 등으로 사선이 막힌 원거리 공격은 실행할 수 없습니다.
- 골짜기는 이동을 제한하지만 그 자체로 원거리 사격을 막지는 않습니다.
- `CoverDurability`의 HP가 0이 되면 엄폐물의 표시·충돌·엄폐·이동/사선 차단 기여를 제거합니다. 직사 폭발무기는 엄폐물 선택 후 Fire로, 곡사 폭발무기는 범위 피해로 파괴할 수 있습니다.
- 오브젝트 데이터가 연결된 시설은 빔·실탄·폭발·근접무기로 공격할 수 있습니다. 시설은 기본 무기 피해를 사용하며 직접 공격은 확정 명중입니다. 원거리는 AP·탄약, 근접은 AP만 소비합니다. 일반 엄폐물은 폭발무기 전용을 유지합니다.

### 무기 선택과 공격

- `Attack`에서 장착한 왼손·오른손·백팩 무기를 이름으로 선택합니다. 양손 파지 무기는 한 번만 표시합니다.
- 원거리 공격은 적과 조준 부위를 선택한 뒤 명중률·피해 범위·AP 비용을 확인하고 `Fire`로 확정합니다.
- 근접 공격은 접근 가능한 몸통을 공격하며 엄폐와 부위 조준 페널티를 적용하지 않습니다.
- 사거리는 가로·세로 거리의 합으로 계산합니다. 장애물이 없는 공격 범위는 마름모 형태입니다.
- 피해는 무기 데이터의 최소~최대 범위에서 정수로 결정합니다.
- 공격 결과는 대상 위에 부위명과 피해 숫자를 약 0.8초 표시합니다. HIT 문구 없이 치명타에만 CRITICAL!을 붙이고 빗나가면 MISS만 표시합니다. 플레이어·적 AI·경계사격이 같은 흐름을 사용하며 다음 행동은 표시 종료 뒤 진행합니다. 곡사 피격 대상은 동시에 표시하고 미탐지 적 정보는 숨깁니다.
- 명중률은 무기 기본 명중률에 기체 명중력/대상 회피력·파일럿 공격 능력치/대상 회피·파지·거리·머리 손상·조준 부위·엄폐 등의 배율을 적용합니다.
- 이동 거리 기록은 유지하지만 **목표의 기동 회피는 현재 명중률에 적용하지 않습니다.**
- 최종 명중률 상한은 **99%**로, 모든 보정 후에도 최소1%의 빗나감 가능성이 남습니다.

일반 공격 AP는 무기별로 설정합니다. 샘플 StandardRifle과 StandardBlade는 AP 3, MS115Rifle은 AP 5를 사용합니다.

### 부위별 내구도와 전투불능

몸통·콕피트·머리·좌우 팔·좌우 다리의 HP를 각각 관리합니다. 단일 전체 HP 대신 부위 상태로 전투 지속 여부를 판단합니다.

| 조건 | 결과 |
|---|---|
| 몸통 또는 콕피트 HP 0 | 즉시 Destroyed |
| 주요 부위 3개 파괴 | 완전파괴 확률 판정 후 생존하면 Critical |
| Critical 상태에서 추가 피격 | 완전파괴 확률 재판정 |
| 주요 부위 4개 이상 파괴 | 즉시 Destroyed |
| 머리 파괴 | 공격 명중률 ×0.75 |
| 한쪽 팔 파괴 | 해당 손의 한손 무기 사용 불가. 양손 필수 무기도 사용 불가 |
| 겸용 무기의 양손 파지 중 한쪽 팔 파괴 | 살아 있는 손의 한손 파지로 자동 전환, 양손 명중 보너스 해제·추가 AP 없음 |
| 양쪽 팔 파괴 | 모든 손 장착 무기 사용 불가 |
| 한쪽 다리 파괴 | 이동 범위 절반, 내림 처리·최소 1칸 |
| 양쪽 다리 파괴 | 이동 불가 |

팔 제한은 아군·적의 근접/원거리 공격과 경계사격에 공통 적용합니다. 기존 한손 무기는 반대 손으로 자동 이전하지 않으며, 무기 사용 불가 또는 파지 전환 시 해당 경계를 해제합니다. 겸용 무기의 전환은 전투 중 장착 상태에만 반영하고, 현재 고정 모델의 무기 위치를 옮기는 연출은 없습니다.

주요 부위는 머리와 좌우 팔·다리입니다. 완전파괴 확률의 코드 기본값은 25%이며 유닛 설정으로 변경할 수 있습니다.

Critical 상태에서는 이동·공격을 할 수 없지만 AP 1로 긴급탈출할 수 있습니다. 정상 상태에서도 탈출할 수 있으며, 탈출한 기체는 해당 전투에서 다시 사용할 수 없습니다. 파일럿의 탈출 후 생존·부상·사망 결과는 아직 구현하지 않았습니다.

### 시야와 전장의 안개

- 탐지 거리와 건물의 시야 차단으로 발견 여부를 판단합니다. 전투 시작 시 시야 안의 적도 바로 탐지합니다.
- 발견하지 못한 적은 숨기고 공격 대상으로 선택할 수 없게 합니다.
- 현재 시야 밖과 미탐험 영역을 구분해 어둡게 표시합니다. 지형·장애물·엄폐물의 형태는 남겨 둡니다.
- 적 AI는 발견한 적이 없으면 대기합니다. 이전 발견 위치를 기억해 추적하는 기능은 없습니다.

### 적 AI

- 발견한 아군을 대상으로 사용 가능한 무기를 확인합니다.
- 바로 공격할 수 있으면 공격하고, 필요하면 사거리로 접근한 뒤 공격을 시도합니다.
- 피격 후에도 행동 가능 여부를 다시 검사하며, 전투불능이면 행동을 중단합니다.
- 행동 중인 적 기체를 바닥의 빨간 테두리로 표시합니다.

### 경계사격 — Overwatch

```text
기체 선택 → Overwatch → 원거리 무기 → 감시 방향 → Confirm / AP 2
```

- 선택 방향의 전방 90도와 무기 사거리 안을 감시합니다. 사수 개인의 시야와 사선 조건도 만족해야 합니다.
- 적이 유효한 칸으로 이동하면 부위 조준창이 열리고 이동이 멈춥니다. 부위별 명중률을 확인해 Fire 또는 Skip을 선택합니다. 명중률은 일반 계산에 ×0.75를 적용합니다.
- 진입 AP는 2, 반응 발사/Skip의 추가 AP는 0입니다. 각 적에게 한 번씩 기회가 있으며 명중·빗나감·Skip 후에도 다른 적에 대한 경계는 유지합니다.
- 경계 중 일반 이동·공격은 제한하며, 결정 대기 중에는 ESC·일반 선택·턴 종료·탈출도 제한합니다. 카메라는 조작할 수 있습니다. 결정 대기 밖에서는 조건과 남은 AP로 탈출할 수 있습니다.
- 경계는 다음 자기 진영 턴 시작 시 만료합니다. 처리한 적은 범위를 나갔다 돌아와도 다시 묻지 않습니다.
- 적 AI는 현재 스스로 경계에 진입하지 않습니다.

### 백팩 추가무장

- 백팩과 포함 무장을 일체형 장비로 장착합니다. 무장 백팩당 무기는1개이며 무장 없는 백팩과 미장착도 가능합니다.
- 손을 점유하지 않아 양손 무기와 함께 사용할 수 있습니다. 팔 파괴만으로 백팩 사용이 막히지 않으며 유닛의 전투불능 규칙은 공통 적용합니다.
- 원거리 백팩은 시작 장탄만 사용하고 예비 탄약0·재장전 불가입니다. 같은 WeaponData를 공유해도 손 무기 및 다른 유닛과 잔탄이 독립적입니다.
- Attack/Overwatch 목록에서 선택하며 잔탄과 재장전 불가를 표시합니다. Reload 목록에서는 제외합니다. 적 AI도 기존 공통 공격 경로를 사용합니다.
- Inspector에서 빈 무기 + 장전·예비 탄약 + 백팩의 총 장착 중량을 확인할 수 있습니다. 기체 한도가 양수이면 초과 장착과 출격을 차단하며, 한도0은 제한 미설정입니다. 예비 탄창·팩 개수는 기체별 UnitWeaponLoadout에서 선택하고, 본체 중량과 만탄 탄창·팩 하나의 중량은 WeaponData에서 따로 지정합니다. 자동 모델 부착은 아직 없습니다.

샘플은 `Assets/_Game/Data/Backpacks/SampleUnarmedBackpack.asset`, `SampleWeaponBackpack.asset`입니다. 기존 씬에는 자동 장착하지 않았습니다. 연결 방법과 범위는 [백팩 사용 안내](docs/backpack-equipment.ko.md)를 참고하세요.

### 데이터 분리와 모델

| 데이터·컴포넌트 | 역할 |
|---|---|
| `MechaData` | 기체 ID·이름·설명, 기본 AP, 명중력·회피력(각0~50), 실탄·빔 받는 피해율(각50~150%), 기본 탐지 거리, 부위 최대 HP, 모델, 이동 효율·중량 관련 정의 |
| `WeaponData` | 무기 이름·설명·특성 목록, 공격 종류, 피해 범위, 명중률, 사거리, 공격 AP, 파지, 거리별 명중 배율, 무기/탄창 중량 |
| `BackpackData` | 백팩 ID·이름·설명, 자체 중량, 선택적인 포함 무장1개와 모델 참조 |
| `DestructibleObjectData` / `TurretData` | 단일 HP 시설 정의와 AP·탐지·원거리 무장을 추가한 고정포대 정의. 시설은 내구도/파괴 임무에 연결하며 포대 동작은 아직 미연결 |
| `MissionData` | 임무 ID·이름·설명·지역 표시·섬멸 대상 적 집단 ID. 지정 집단의 Destroyed 목표에 연결 |
| `CharacterData` | 파일럿 이름·설명·초기 레벨·사격·근접·기량·회피의 초기 정의 |
| `UnitWeaponLoadout` | 유닛의 왼손·오른손 무기·파지·출격 예비 개수·백팩 설정, 탄약 포함 총 장착 중량 계산 |
| `UnitWeaponAmmo` | 유닛별 각 손·백팩의 잔탄과 예비 탄약 상태, 슬롯별 재장전 가능 여부 |
| `BattleUnit` | 기체 데이터를 읽어 유닛별 HP·AP·외형 초기화 연결 |
| `UnitHealth` / `UnitActionPoints` | 전투 중 현재 부위 HP·AP와 상태 관리 |

원거리 무기는 빔·실탄·폭발물, 근접 무기는 날붙이·둔기로 분류합니다. 한손 전용·양손 필수·양쪽 모두 가능한 파지 조건을 지원합니다. 직사 폭발물에는 무기별 추가 부위 수·최소/최대 피해 배율·추첨 간격(%p, 기본5)을 설정할 수 있습니다. 예를 들어0~20%, 간격5이면0/5/10/15/20% 중에서 부위마다 균등 추첨합니다. 같은 적의 직격 부위·콕피트·파괴된 부위를 제외하고 중복 없이 골라 추가 피해를 주며 모든 HP를 반영한 뒤 상태를 한 번 판정합니다. 추가 부위 수 기본0은 비활성입니다. [폭발 부위 피해 안내](docs/explosive-part-damage.ko.md)를 참고하세요.

**곡사 폭발물**은 사거리 안의 좌표를 골라 마름모 범위의 기체에 확정 피해를 줍니다. 무기별 최소/최대 피격 부위 수와 부위당 피해를 독립 추첨합니다. 아군·자신·미탐지 적도 맞으며 건물은 폭발을 차단합니다. 미탐지 적의 정보는 미리보기와 결과에 숨깁니다. 적 AI도 발견한 적 위치로 안전한 곡사를 사용하고 곡사는 경계에서 제외합니다. [곡사 사용 안내](docs/indirect-explosive.ko.md)를 참고하세요.

WeaponData의 **무기 특성** 목록에서 `건물 너머 곡사 가능`을 지정할 수 있습니다. 기본 곡사무기는 큰 건물에 발사가 막히고, 이 특성이 있으면 건물 너머로 발사할 수 있습니다. 특성은 사거리나 착탄 후 폭발 차단에는 영향을 주지 않습니다. 기존 무기에 특성을 자동 부여하지 않았습니다. [무기 특성 안내](docs/weapon-traits.ko.md)를 참고하세요.

기체의 **실탄·빔 받는 피해(%)**를 MechaData에서 각각50~150으로 설정합니다. 100은 보정 없음이며 낮을수록 강합니다. 기존 장갑 타입은 호환해서 읽으며 직접 지정한 피해율과 중복 계산하지 않습니다. 기체별 최종 배율 조회 함수를 두어 추후 추가부품 보정을 연결할 수 있습니다. 폭발·근접의 기존 규칙은 유지합니다. [피해율 안내](docs/damage-taken-percent.ko.md)를 참고하세요.

파일럿은 전투 시작 시 사격·근접·기량·회피를 각각0~50으로 읽습니다. 원거리 명중 배율은 `1 + (사격−대상 회피)×.01`, 근접 명중 배율은 `1 + (근접−대상 회피)×.005`, 근접 피해 배율은 `1 + 근접×.005`입니다. 기량은 치명타 확률에 적용하며 기본 치명타 피해는×1.25입니다. 파일럿이 없으면 각 능력치는0입니다. 일반 공격·적 AI·경계사격에 공통 적용합니다.

파일럿 패시브는 인터페이스만 준비되어 있고 효과는 연결하지 않았습니다. 기체의 AP당 이동거리는 실제 비용에 적용하며 자기 턴 동안 선불 이동 여유를 유지합니다. 이동·사격·이동을 나눠도 누적 비용은 같고, 다리 하나 파괴 시 이후 이동 효율이 절반이 됩니다. [이동 AP 안내](docs/movement-ap.ko.md)를 참고하세요. 빈 무기·장전/예비 탄약·백팩의 합계를 장착 중량 한도와 비교하여 초과 장착과 전투 시작을 차단합니다. 한도0은 제한 미설정이며 한도와 같은 중량은 허용합니다. 기존 초과 장비의 해제와 예비 개수 감소는 가능하지만 한도 안으로 줄여야 출격할 수 있습니다. 중량에 따른 이동력 감소와 전투 중 사용량에 따른 중량 감소는 적용하지 않습니다.

기체 명중력·회피력은 전투 시작 시 읽어 공격에 적용합니다. 두 수치가 같으면 ×1, 50대0이면 ×1.5, 0대50이면 ×0.6입니다. 기본값0으로 기존 에셋의 전투 수치는 유지합니다. 계수 조절 위치는 [명중률 밸런싱 안내](docs/hit-chance-balancing.ko.md)를 참고하세요.

기체의 **기본 탐지 거리 (칸)**는 MechaData에서 조절합니다. 기본10칸이며0은 탐지 반경0입니다. BattleUnit이 전투 시작 시 UnitVision에 적용하여 기존 탐지·전장의 안개·AI에 반영합니다. MechaData가 없는 유닛은 기존 UnitVision 설정을 유지합니다. 실행 중 기체 에셋을 수정했다면 전투를 다시 시작해야 하며 추가부품·머리 손상 보정은 아직 없습니다.

전투 로직과 외형을 분리하고 기체 데이터의 모델 프리팹을 연결했습니다. 샘플 메카·라이플 모델과 무기의 손잡이·총구 기준점도 준비되어 있습니다.

## 기본 조작

| 입력 | 동작 |
|---|---|
| 아군 왼쪽 클릭 | 기체 선택·행동 메뉴 표시 |
| 탐지한 적 왼쪽 클릭 | 읽기 전용 기체명·외형·부위 HP·장착 무기 확인. 공격 준비 중이면 기존 조준 대상 지정 |
| 아군 더블클릭 | 카메라를 해당 기체 중심으로 이동 |
| `Move` → 목적지 클릭 | 이동 범위 확인 후 이동 |
| 이동 후 방향 → `Confirm` | 최종 방향 확정 |
| `Attack` → 무기 → 적·부위 → `Fire` / `Strike` | 원거리 / 근접 공격 확정 |
| `Overwatch` → 원거리 무기 → 방향 → `Confirm` | 경계 진입 |
| 경계 반응 부위 선택 → Fire / Skip | 적별 사격 또는 건너뛰기 결정, 추가 AP 없음 |
| Eject | AP 1로 긴급탈출 |
| `End Turn` | 플레이어 진영 턴 종료 |
| `ESC` | 선택·조준·미확정 준비 해제 |
| `WASD` | 카메라 평행 이동 |
| `Q` / `E` | 카메라를 서로 반대 방향으로 90도씩 부드럽게 회전 |
| 마우스 휠 | 줌인·줌아웃 |

선택 해제는 이미 소비한 AP나 실행한 이동을 되돌리지 않습니다. 확정된 경계도 ESC로 취소되지 않습니다. 경계 결정창에서는 Fire/Skip으로 결정하며 ESC를 무시합니다. 현재 기체의 최종 방향에 따른 부위 노출·명중률 보정은 적용하지 않습니다.

## 프로젝트 구성

```text
Assets/_Game/
├ Scripts/       # Grid·Unit·Combat·Cover·Turn·AI·Input·Presentation 등
├ Scenes/        # 전투 검증 씬
├ Data/          # 기체·무기·파일럿 데이터 에셋
├ Prefabs/       # 유닛과 외형 프리팹
├ Materials/
├ Art/           # 샘플 모델과 부위 조준 UI 이미지
└ Tests/         # EditMode·PlayMode·공유 테스트 지원 코드
docs/           # 설계·사용 안내·현재 아키텍처
tools/          # Unity 테스트 실행 도구
```

`docs/`는 개발 참고 문서이며 게임 실행·빌드에 필수인 폴더는 아닙니다. Unity의 `Assets/`, `Packages/`, `ProjectSettings/`와 에셋의 `.meta` 파일은 프로젝트 구성과 참조 유지에 사용합니다.

## 테스트

Unity의 **Window → General → Test Runner**에서 EditMode·PlayMode 테스트를 실행할 수 있습니다. 그리드·엄폐·명중률·무기/기체 데이터 검증과 실제 이동·입력·카메라·적 AI·시야·샘플 씬·경계사격 통합 테스트를 포함합니다.

Windows에서는 프로젝트 루트에서 아래 도구도 사용할 수 있습니다. Unity에서 같은 프로젝트를 열고 있다면 먼저 종료하고, 스크립트의 Unity 실행 경로가 설치 위치와 맞는지 확인합니다.

```powershell
.\tools\Run-UnityTests.ps1 -Mode EditMode -Name editmode
.\tools\Run-UnityTests.ps1 -Mode PlayMode -Graphics -Name playmode
```

로그와 XML 결과는 `Artifacts/`에 생성됩니다. 이 폴더는 현재 `.gitignore`의 제외 대상입니다.

**마지막 전체 검증: 2026-11-09 — EditMode 1029/1029, 그래픽 PlayMode 470/470 통과, 실패·건너뜀 0.** 지정 집단 섬멸·특정 메카/통신소 파괴·데이터 HP·실제 시설 마우스 조준/Fire·팝업 후 성공·Critical/탈출/삭제 제외·진행도 수명·설정 검증·원본 씬 보호, 임무 공통 실패·팝업 대기·종료 정리·기존 씬 호환도 검증했습니다. 원본 프로젝트를 보존한 테스트 복제본에서 실행했으며, 네 저장 씬의 런타임 연결과 실제 입력/AI를 포함합니다. 기체별 턴 누적 이동 AP·이동-사격-이동·다리 손상·소수 효율·AI 예산, 기체별 피해율·이전 장갑 호환·일반/경계/AI 피해, 무기 특성·곡사 건물 차단·이동 후 발사, 기체별 예비 개수·탄창 중량·장착 한도도 검증했습니다. 엄폐물 HP·겹침/파괴 후 차단 해제·직사 클릭/Fire·곡사 범위/AI·벽 뒤 대상 보호·무기 전환/ESC·피해 오버플로도 포함합니다. 공통 공격 팝업의 영어 부위명·실제 피해·빗나감·치명타·표시 중 행동 차단·곡사/미탐지 보호·경계 다음 사수 대기·마지막 타격 후 전투 종료도 검증했습니다. 적 기체 정보 선택의 행동 권한·시야 보호·진영별 외곽선과 실제 모델 미리보기의 색상/위아래 방향/원본 불변/자원 해제도 포함합니다.
