# MechaXCOM

메카 용병단을 지휘하며 지형·엄폐·무장·기체 손상을 관리하는 **Unity 기반 3D 턴제 전술 게임** 프로젝트입니다.

`기동전사 건담 제08MS소대`처럼 흙먼지 나는 육상전을 지향합니다. 메카를 거대한 보병 또는 장갑전투차량처럼 다루며, 건물과 폐허를 이용한 엄폐, 소대 단위의 우회와 집중 사격, 위험한 기체의 탈출 판단을 전투의 중심에 둡니다.

현재는 **전투 시스템을 검증하는 프로토타입**입니다. 용병단 운영과 캠페인보다 이동·공격·부위 손상·시야·경계사격의 기초를 먼저 구현하고 있습니다.

## 게임의 방향

플레이어는 한 명의 파일럿이 아닌 용병단의 지휘관입니다. 장기적으로는 3~5기의 소대를 구성하고, 파일럿과 기체·무장을 배정해 임무에 투입하는 흐름을 목표로 합니다.

```text
용병단 기지 → 의뢰 선택 → 파일럿·기체·무장 편성 → 출격
→ 턴제 전투 → 승리 / 실패 / 철수 → 수리·보충·파일럿 관리
```

목표는 적을 격파하는 것과 함께 파일럿과 기체를 살아서 돌아오게 만드는 것입니다. 탄약 관리, 파일럿 생존과 영구 사망, 관계 변화, 임무 후 정비 등은 향후 개발 대상입니다.

## 실행 방법

1. Unity Hub에서 프로젝트 루트 폴더를 엽니다.
2. 프로젝트 기준 에디터 버전인 **Unity 6000.5.5f1**을 사용합니다. 렌더 파이프라인은 URP입니다.
3. 다음 샘플 씬 중 하나를 열고 Play를 누릅니다.

| 씬 | 용도 |
|---|---|
| [SqurdWeaponTest](Assets/_Game/Scenes/SqurdWeaponTest.unity) | 아군·적 각각 3기의 소대전과 장착 무기 검증 |
| [1V1Test](Assets/_Game/Scenes/1V1Test.unity) | 소규모 전투 규칙 검증 |

`SqurdWeaponTest`는 현재 파일 이름 그대로 표기했습니다. 샘플 수치와 배치는 씬 및 데이터 에셋 설정에 따라 달라질 수 있습니다.

## 현재 구현된 기능

### 그리드 이동과 진영 턴

- 3D 맵에서 Grid 기반 이동·점유·경로 탐색을 처리합니다.
- 상하좌우로 이동하며 이동 범위와 남은 AP에 맞는 칸을 표시합니다.
- 유닛·장애물이 점유한 칸과 골짜기 등 이동 불가 칸을 통과할 수 없습니다.
- 이동 경로 한 칸마다 AP 1을 소비하며 모델이 진행 방향을 바라봅니다.
- 이동 후 북·동·남·서 중 최종 방향을 선택할 수 있습니다.
- 플레이어 진영과 적 진영이 번갈아 행동합니다. 각 기체는 독립적인 AP를 가지며 자기 진영 턴 시작 시 최대치로 회복합니다.
- 기본 AP는 5이며 기체 데이터로 변경할 수 있습니다.

### 엄폐와 사선

- Half / Full Cover를 방향별로 관리합니다.
- 상하좌우 공격은 해당 방향 엄폐를 사용합니다. 대각선 공격은 해당 대각선과 양옆 방향 중 가장 강한 엄폐 하나를 사용합니다.
- 기본 명중 배율은 Half Cover ×0.75, Full Cover ×0.5입니다.
- 건물 등으로 사선이 막힌 원거리 공격은 실행할 수 없습니다.
- 골짜기는 이동을 제한하지만 그 자체로 원거리 사격을 막지는 않습니다.

### 무기 선택과 공격

- `Attack`에서 장착한 왼손·오른손 무기를 이름으로 선택합니다. 양손 파지 무기는 한 번만 표시합니다.
- 원거리 공격은 적과 조준 부위를 선택한 뒤 명중률·피해 범위·AP 비용을 확인하고 `Fire`로 확정합니다.
- 근접 공격은 접근 가능한 몸통을 공격하며 엄폐와 부위 조준 페널티를 적용하지 않습니다.
- 사거리는 가로·세로 거리의 합으로 계산합니다. 장애물이 없는 공격 범위는 마름모 형태입니다.
- 피해는 무기 데이터의 최소~최대 범위에서 정수로 결정합니다.
- 명중률은 무기 기본 명중률에 파지·거리·머리 손상·조준 부위·엄폐 등의 배율을 적용합니다.
- 이동 거리 기록은 유지하지만 **목표의 기동 회피는 현재 명중률에 적용하지 않습니다.**

일반 공격 AP는 무기별로 설정합니다. 샘플 StandardRifle과 StandardBlade는 AP 3, MS115Rifle은 AP 5를 사용합니다.

### 부위별 내구도와 전투불능

몸통·콕피트·머리·좌우 팔·좌우 다리의 HP를 각각 관리합니다. 단일 전체 HP 대신 부위 상태로 전투 지속 여부를 판단합니다.

| 조건 | 결과 |
|---|---|
| 몸통 또는 콕피트 HP 0 | 즉시 Destroyed |
| 주요 부위 3개 파괴 | 완전파괴 확률 판정 후 생존하면 Critical |
| Critical 상태에서 추가 피격 | 완전파괴 확률 재판정 |
| 주요 부위 4개 이상 파괴 | 즉시 Destroyed |
| 머리 파괴 | 공격 명중률 ×0.75 |
| 한쪽 다리 파괴 | 이동 범위 절반, 내림 처리·최소 1칸 |
| 양쪽 다리 파괴 | 이동 불가 |

주요 부위는 머리와 좌우 팔·다리입니다. 완전파괴 확률의 코드 기본값은 25%이며 유닛 설정으로 변경할 수 있습니다.

Critical 상태에서는 이동·공격을 할 수 없지만 AP 1로 긴급탈출할 수 있습니다. 정상 상태에서도 탈출할 수 있으며, 탈출한 기체는 해당 전투에서 다시 사용할 수 없습니다. 파일럿의 탈출 후 생존·부상·사망 결과는 아직 구현하지 않았습니다.

### 시야와 전장의 안개

- 탐지 거리와 건물의 시야 차단으로 발견 여부를 판단합니다. 전투 시작 시 시야 안의 적도 바로 탐지합니다.
- 발견하지 못한 적은 숨기고 공격 대상으로 선택할 수 없게 합니다.
- 현재 시야 밖과 미탐험 영역을 구분해 어둡게 표시합니다. 지형·장애물·엄폐물의 형태는 남겨 둡니다.
- 적 AI는 발견한 적이 없으면 대기합니다. 이전 발견 위치를 기억해 추적하는 기능은 없습니다.

### 적 AI

- 발견한 아군을 대상으로 사용 가능한 무기를 확인합니다.
- 바로 공격할 수 있으면 공격하고, 필요하면 사거리로 접근한 뒤 공격을 시도합니다.
- 피격 후에도 행동 가능 여부를 다시 검사하며, 전투불능이면 행동을 중단합니다.
- 행동 중인 적 기체를 바닥의 빨간 테두리로 표시합니다.

### 경계사격 — Overwatch

```text
기체 선택 → Overwatch → 원거리 무기 → 감시 방향 → Confirm / AP 2
```

- 선택 방향의 전방 90도와 무기 사거리 안을 감시합니다. 사수 개인의 시야와 사선 조건도 만족해야 합니다.
- 적이 한 칸 이동을 완료하면 몸통에 한 번 반응 사격합니다. 명중률은 일반 계산에 ×0.75를 적용합니다.
- 진입 시 AP 2를 소비하며, 발사 시 추가 AP는 없습니다. 빗나가도 경계를 소모합니다.
- 경계 중 일반 이동·공격은 제한하지만 남은 AP로 탈출할 수 있습니다.
- 발사하지 않은 경계는 다음 자기 진영 턴 시작 시 만료합니다.
- 적 AI는 현재 스스로 경계에 진입하지 않습니다.

### 데이터 분리와 모델

| 데이터·컴포넌트 | 역할 |
|---|---|
| `MechaData` | 기체 ID·이름·설명, 기본 AP, 부위 최대 HP, 모델, 이동 효율·중량 관련 정의 |
| `WeaponData` | 무기 이름·설명, 공격 종류, 피해 범위, 명중률, 사거리, 공격 AP, 파지, 거리별 명중 배율, 중량 |
| `CharacterData` | 파일럿 이름·설명·초기 레벨·사격·근접·기량·회피의 초기 정의 |
| `UnitWeaponLoadout` | 유닛의 왼손·오른손 무기와 파지 설정 |
| `BattleUnit` | 기체 데이터를 읽어 유닛별 HP·AP·외형 초기화 연결 |
| `UnitHealth` / `UnitActionPoints` | 전투 중 현재 부위 HP·AP와 상태 관리 |

원거리 무기는 빔·실탄·폭발물, 근접 무기는 날붙이·둔기로 분류합니다. 한손 전용·양손 필수·양쪽 모두 가능한 파지 조건을 지원합니다. 분류만으로 폭발 범위나 별도의 피해 효과가 발생하지는 않습니다.

파일럿 패시브 인터페이스도 준비되어 있지만 파일럿 능력치·패시브는 아직 전투 계산에 연결하지 않았습니다. 기체의 AP당 이동거리와 중량, 무기 중량도 데이터 저장 단계이며 이동 비용·장착 한도에 적용하지 않습니다.

전투 로직과 외형을 분리하고 기체 데이터의 모델 프리팹을 연결했습니다. 샘플 메카·라이플 모델과 무기의 손잡이·총구 기준점도 준비되어 있습니다.

## 기본 조작

| 입력 | 동작 |
|---|---|
| 아군 왼쪽 클릭 | 기체 선택·행동 메뉴 표시 |
| 아군 더블클릭 | 카메라를 해당 기체 중심으로 이동 |
| `Move` → 목적지 클릭 | 이동 범위 확인 후 이동 |
| 이동 후 방향 → `Confirm` | 최종 방향 확정 |
| `Attack` → 무기 → 적·부위 → `Fire` / `Strike` | 원거리 / 근접 공격 확정 |
| `Overwatch` → 원거리 무기 → 방향 → `Confirm` | 경계 진입 |
| `Eject` | AP 1로 긴급탈출 |
| `End Turn` | 플레이어 진영 턴 종료 |
| `ESC` | 선택·조준·미확정 준비 해제 |
| `WASD` | 카메라 평행 이동 |
| `Q` / `E` | 카메라를 서로 반대 방향으로 90도씩 부드럽게 회전 |
| 마우스 휠 | 줌인·줌아웃 |

선택 해제는 이미 소비한 AP나 실행한 이동을 되돌리지 않습니다. 확정된 경계도 ESC로 취소되지 않습니다. 현재 기체의 최종 방향에 따른 부위 노출·명중률 보정은 적용하지 않습니다.

## 프로젝트 구성

```text
Assets/_Game/
├ Scripts/       # Grid·Unit·Combat·Cover·Turn·AI·Input·Presentation 등
├ Scenes/        # 전투 검증 씬
├ Data/          # 기체·무기·파일럿 데이터 에셋
├ Prefabs/       # 유닛과 외형 프리팹
├ Materials/
├ Art/           # 샘플 모델과 부위 조준 UI 이미지
└ Tests/         # EditMode·PlayMode·공유 테스트 지원 코드
docs/           # 설계·사용 안내·현재 아키텍처
tools/          # Unity 테스트 실행 도구
```

`docs/`는 개발 참고 문서이며 게임 실행·빌드에 필수인 폴더는 아닙니다. Unity의 `Assets/`, `Packages/`, `ProjectSettings/`와 에셋의 `.meta` 파일은 프로젝트 구성과 참조 유지에 사용합니다.

## 테스트

Unity의 **Window → General → Test Runner**에서 EditMode·PlayMode 테스트를 실행할 수 있습니다. 그리드·엄폐·명중률·무기/기체 데이터 검증과 실제 이동·입력·카메라·적 AI·시야·샘플 씬·경계사격 통합 테스트를 포함합니다.

Windows에서는 프로젝트 루트에서 아래 도구도 사용할 수 있습니다. Unity에서 같은 프로젝트를 열고 있다면 먼저 종료하고, 스크립트의 Unity 실행 경로가 설치 위치와 맞는지 확인합니다.

```powershell
.\tools\Run-UnityTests.ps1 -Mode EditMode -Name editmode
.\tools\Run-UnityTests.ps1 -Mode PlayMode -Graphics -Name playmode
```

로그와 XML 결과는 `Artifacts/`에 생성됩니다. 이 폴더는 현재 `.gitignore`의 제외 대상입니다.

**마지막 전체 검증 기록: 2026-10-20 — EditMode 460/460, PlayMode 267/267 통과, 실패·건너뜀 0.** README 작성 시 테스트를 다시 실행한 결과는 아닙니다.

## 아직 구현하지 않은 주요 기능

- 캠페인·의뢰·소대 편성·용병단 운영·저장/불러오기
- 파일럿 레벨업·포인트 분배·전투 능력치 반영·관계·영구 사망
- 탄약 소비·재장전·보급·수리·소대 철수
- 폭발 범위 공격·엄폐물 내구도·부스트·근접 교전 제한
- 팔 파괴에 따른 무장 사용 제한과 장착 중량 제한
- 전투 중 무기 교체·파지 전환과 적 AI의 경계 선택
